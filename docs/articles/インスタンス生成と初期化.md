# C++ インスタンス生成と初期化の完全整理

C#やPythonからC++に入ると、「インスタンスをどう作るのか」でまず躓く。
原因は一つだ。

> C++の初期化には複数の方法があり、それぞれ意味が違う。

このドキュメントでは、戸惑いの正体を言語化し、選択基準まで整理する。

---

## 第1章：C#との最大のギャップ —— `new` は必須ではない

### C#出身者の刷り込み

C#では参照型のインスタンス生成に `new` が必須だ。

```csharp
// C#
Apple apple = new Apple();  // new がないとコンパイルエラー
```

この感覚のまま C++ を読むと、`new` のないコードを見たとき
「これはインスタンス生成になっていないのでは？」と思う。

### C++の現実

C++では `new` なしでインスタンスが作られる。

```cpp
Apple apple;  // これだけで Apple のインスタンスが生成される
              // コンストラクタも呼ばれる
```

これは完全にインスタンス生成だ。

### `new` を使うとどう違うのか

| 項目 | `Apple apple;` | `Apple* apple = new Apple;` |
| :--- | :--- | :--- |
| **生成場所** | スタック | ヒープ |
| **寿命管理** | スコープを抜けると自動破棄 | `delete` するまで生き続ける |
| **`delete` の必要性** | 不要 | 必要（しないとメモリリーク） |
| **C++での位置づけ** | **基本（こちらを使う）** | 寿命を自分で管理したいとき |

```cpp
void func()
{
    Apple apple;   // スタックに生成
}                  // ← ここでデストラクタが自動で呼ばれる

Apple* p = new Apple;  // ヒープに生成
delete p;              // 自分で解放しないといけない
```

### 結論

> C++では「`new` を使わない生成」が基本。
> `new` はヒープに生成して寿命を自分で管理したいときに限って使う。

## 第2章：3つの書き方と初期化の差

### 3つの記法

```cpp
Apple a;              // ① デフォルト初期化
Apple b{};            // ② 値初期化（波かっこ）
Apple* c = new Apple; // ③ 動的生成（ヒープ）

delete c;
```

全部インスタンス生成だ。
違うのは「どこに作るか」と「どう初期化するか」。

### クラス型の場合はほぼ同じに見える

クラスにデフォルトコンストラクタがあれば、① と ② はどちらもそのコンストラクタを呼ぶ。

```cpp
class Apple
{
public:
    int price;

    Apple() : price{100}
    {
    }
};

Apple a;    // price = 100
Apple b{};  // price = 100
```

動作は同じに見える。しかし言語仕様上は別物だ。

### 違いが出る場面

#### 組み込み型（プリミティブ型）では決定的に違う

```cpp
int x;    // 未初期化。何が入っているかわからない（ゴミ値）
int y{};  // 0 で初期化される
```

`int x;` の `x` をそのまま使うのは危険だ。
`{}` をつけると安全側に倒れる。

#### メンバ変数に初期化がない場合も違う

```cpp
class Apple
{
public:
    int price;  // コンストラクタで初期化していない
};

Apple a;    // price は不定値（ゴミが入っている可能性）
Apple b{};  // price は 0 になる
```

#### 危険な型変換を防ぐ

```cpp
int x = 3.14;   // コンパイルが通る（3 に切り捨て）
int y{3.14};    // コンパイルエラーになる
```

`{}` は **narrowing conversion（縮小変換）** を禁止する。
バグを未然にコンパイルエラーにできる。

### 選択基準

| 状況 | 推奨 |
| :--- | :--- |
| クラスのインスタンスを普通に作りたい | `Apple a{};` |
| 既存コードを読む（両方出てくる） | どちらも正しいと判断する |
| 組み込み型の変数 | `int x{};` で初期化を明示する |

> 迷ったら `{}` をつけておくと、初期化漏れ・縮小変換の2つのリスクを減らせる。

## 第3章：コンストラクタ初期化子リスト

### この構文が最初に謎に見える

```cpp
class Apple
{
public:
    Apple() : price{100}   // ← この「: price{100}」は何？
    {
    }

private:
    int price;
};
```

C#出身者には `:` の後ろが唐突に見える。
これが **コンストラクタ初期化子リスト**（member initializer list）だ。

### 構文の読み方

```
コンストラクタ名() : メンバ名{値}, メンバ名{値}
{
    // コンストラクタ本体
}
```

`:` の後ろで「このメンバをこの値で初期化する」を宣言している。

複数メンバがある場合はカンマで並べる。

```cpp
class Player
{
public:
    Player(int hp, int mp) : hp_{hp}, mp_{mp}
    {
    }

private:
    int hp_;
    int mp_;
};
```

### 「本体での代入」との本質的な違い

C#の感覚では、コンストラクタの中で代入すれば同じに思える。

```csharp
// C#
public Apple()
{
    this.price = 100;  // コンストラクタ本体で代入
}
```

C++でも書けるし、動く。

```cpp
class Apple
{
public:
    Apple()
    {
        price = 100;  // 本体で代入
    }

private:
    int price;
};
```

しかし内部の動作が違う。

| 方法 | 実際の流れ |
| :--- | :--- |
| **初期化子リスト** | `price` を `100` で **作る** （1ステップ） |
| **コンストラクタ本体での代入** | `price` をデフォルトで **作ってから** `100` を **代入する** （2ステップ） |

`int` のような単純な型では差が見えにくい。
しかしクラス型のメンバになると差が大きくなる。

### 初期化子リストが必須になる3パターン

#### 1. `const` メンバ

```cpp
class Config
{
public:
    Config() : maxCount{10}   // OK
    {
    }

    // これはダメ
    // Config()
    // {
    //     maxCount = 10;  // エラー: const には代入できない
    // }

private:
    const int maxCount;
};
```

`const` は「後から代入」ができない。最初から値を持って生まれないといけない。

#### 2. 参照メンバ

```cpp
class View
{
public:
    View(int& data) : data_{data}  // OK
    {
    }

private:
    int& data_;  // 参照は宣言時に紐付けが必要
};
```

参照は再束縛できない（`参照とポインタの使い分け.md` 参照）。
作る瞬間に何かを指していないといけない。

#### 3. クラス型のメンバ（デフォルトコンストラクタがない場合）

```cpp
class Price
{
public:
    Price(int v) : value_{v} {}  // デフォルトコンストラクタなし

    int value_;
};

class Apple
{
public:
    Apple() : price_{100}   // OK。Price(100) で直接構築
    {
    }

    // これはダメ
    // Apple()
    // {
    //     price_ = Price{100};  // エラー: price_ のデフォルト構築に失敗する
    // }

private:
    Price price_;
};
```

### 重要な落とし穴：初期化順は「宣言順」

初期化子リストに書く順番ではなく、**メンバの宣言順**に初期化される。

```cpp
class Broken
{
public:
    Broken(int a)
        : y_{x_ + 10},  // 危険: x_ はまだ初期化されていない
          x_{a}
    {}

private:
    int y_;  // 宣言順: y_ が先
    int x_;  // 宣言順: x_ が後
};
```

`x_` より先に `y_` が宣言されているため、
リストに `: y_{x_ + 10}, x_{a}` と書いても、
実際には `y_` が先に初期化される。このとき `x_` は未初期化だ。

**正しい設計：**

```cpp
class Safe
{
public:
    Safe(int a)
        : x_{a},
          y_{a + 10}    // x_ に依存せず、引数 a から計算する
    {}

private:
    int x_;
    int y_;
};
```

> メンバは互いに依存させない。
> 初期化の値は引数や定数から直接決める。

### クラス外定義のときは `クラス名::` をつける

ヘッダと実装を分けるとき、コンストラクタをクラスの外に書く。
そのときは `クラス名::コンストラクタ名` の形になる。

```cpp
// Apple.h
class Apple
{
public:
    Apple();  // 宣言だけ

private:
    int price;
};

// Apple.cpp
Apple::Apple() : price{100}   // Apple:: をつける
{
}
```

`Apple::` はクラスの外に定義を置く合図だ。
クラスの中に書くときは `Apple::` は不要。

## 第4章：判断基準まとめ

```
インスタンスを作りたい
│
├── 寿命をスコープに任せていい？
│   ├── Yes → Apple a{};  （基本）
│   └── No  → Apple* a = new Apple;  （delete 忘れに注意）
│              または unique_ptr<Apple> を使う（第7章参照）
│
└── メンバの初期化
    ├── const メンバがある        → 初期化子リスト 必須
    ├── 参照メンバがある          → 初期化子リスト 必須
    ├── クラス型メンバがある      → 初期化子リスト が自然
    └── それ以外                 → 初期化子リスト が推奨（コンストラクタ本体も可）
```

## 理解度チェック

以下のコードを読んで、各問いに答えてみてほしい。

```cpp
#include <iostream>
using namespace std;

class Score
{
public:
    Score(int base) : base_{base}, bonus_{base_ * 2}
    {
    }

    void show() const
    {
        cout << base_ << " / " << bonus_ << endl;
    }

private:
    int bonus_;  // 宣言は bonus_ が先
    int base_;   // 宣言は base_ が後
};

int main()
{
    Score s{10};
    s.show();

    return 0;
}
```

**問1:** `base_` と `bonus_` はどちらが先に初期化されるか？

**問2:** `bonus_` の初期化 `: bonus_{base_ * 2}` は安全か？

**問3:** このコードを安全にするにはどう直せばよいか？

---

**正解:**

**問1:** `bonus_` が先に初期化される。
宣言順（`bonus_` → `base_`）が初期化順を決めるため。

**問2:** 安全ではない。
`bonus_` の初期化時点で `base_` はまだ未初期化だ。
`: bonus_{base_ * 2}` は不定値を使う危険な式になっている。

**問3:** 引数 `base` から直接計算するように変える。

```cpp
Score(int base) : bonus_{base * 2}, base_{base}
//                        ↑ base_ ではなく引数 base を使う
{
}
```

または宣言順をリストの意図に合わせる。

```cpp
private:
    int base_;   // 先に宣言する
    int bonus_;  // 後に宣言する
```

> **重要な視点**: リストに書く順序を宣言順に合わせるか、
> メンバ間の依存をなくすかのどちらかで解決する。
