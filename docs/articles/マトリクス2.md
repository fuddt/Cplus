マトリクス補正後はどうなるか

R位置 → 補正後のR値
G位置 → 補正後のG値
B位置 → 補正後のB値

ただし、その補正後の値は、単に

元のR値を少し増やした
元のG値を少し減らした
元のB値を少し増やした

マトリクス補正では、たとえばR位置なら、

補正後R = r0×R相当値 + r1×G相当値 + r2×B相当値

G位置なら、

補正後G = g0×R相当値 + g1×G相当値 + g2×B相当値

B位置なら、

補正後B = b0×R相当値 + b1×G相当値 + b2×B相当値

のように作る。

生Bayer画像:
  各画素は R/G/B のどれか1色の生値
マトリクス補正後Bayer画像:
  各画素は R/G/B のどれか1色の補正後値
違い:
  補正後値は、その色単独ではなく、
  R/G/B相当値を混ぜて作られた値

3色が混ざって調整されたR/G/B

これはかなり近いです。

より正確には、

Bayer上の各画素は1色のままだが、その1色の値を作るときに、R/G/Bの情報を混ぜている

です。

⸻

画素値とは何か

画像は、小さいマスの集まりです。

□ □ □ □
□ □ □ □
□ □ □ □

この1マスが 画素 です。

そして、それぞれの画素には「明るさの数字」が入っています。

たとえば白黒画像なら、

0   = 真っ黒
255 = 真っ白

みたいな感じです。

0     20    80    255
黒    暗い  明るい 白

この 0 や 255 が 画素値 です。

⸻

画素値の段階とは何か

「画素値の段階」というのは、

明るさを何段階で表現できるか

という意味です。

たとえば、もし明るさを4段階しか表現できないなら、

0 = 黒
1 = 暗い灰色
2 = 明るい灰色
3 = 白

です。

かなり粗い画像になります。

一方、256段階なら、

0, 1, 2, 3, ... 255

なので、黒から白まで細かく表現できます。

⸻

bit数と段階数

コンピュータは 0 と 1 で数字を持ちます。

1bitなら、

0
1

の2段階。

2bitなら、

00 = 0
01 = 1
10 = 2
11 = 3

の4段階。

3bitなら、

000 = 0
001 = 1
010 = 2
011 = 3
100 = 4
101 = 5
110 = 6
111 = 7

の8段階。

つまり、

bit数が1増えると、段階数は2倍になる

⸻

よく出る対応

8bit  = 256段階    = 0〜255
10bit = 1024段階   = 0〜1023
12bit = 4096段階   = 0〜4095
16bit = 65536段階  = 0〜65535

ここが今回の 1024 に関係しています。

1024 は、

10bitの画素値を全部表せる数

です。

⸻

1024の意味

10bitの画素値は、

0〜1023

です。

数えると1024個あります。

0
1
2
...
1023

だから、LUTサイズが1024なら、

画素値0用の補正値
画素値1用の補正値
画素値2用の補正値
...
画素値1023用の補正値

を持てるという意味です。

⸻

LUTとは何か

LUTは「対応表」です。

たとえば、こういう表だと思ってください。

入力の明るさ    補正後の値
0              0
1              2
2              4
3              6
...
1023           1023

画像処理では、毎回計算する代わりに、

この画素値なら、この補正値を使う

と表から引くことがあります。

これがLUTです。

⸻

学校の例で言うと

テストの点数を補正する表だと思ってください。

元の点数    補正後の点数
0点         0点
1点         2点
2点         3点
3点         5点
...
100点       100点

生徒の点数が 80点 なら、表の80番目を見る。

80点 → 83点

この「点数ごとの変換表」がLUTです。

画像の場合は、点数ではなく画素値です。

画素値300 → 補正値○○
画素値500 → 補正値○○
画素値900 → 補正値○○

⸻

今回の value[4][1024] の意味

これを分解すると、

value[4][1024]

はこうです。

1024個の表が、4本ある

もう少し正確には、

value[0][0〜1023]
value[1][0〜1023]
value[2][0〜1023]
value[3][0〜1023]

です。

つまり、

LUT 0番
LUT 1番
LUT 2番
LUT 3番

の4本を持っている。

⸻

value[16][1024] の意味

同じように、

value[16][1024]

は、

1024個の表が、16本ある

です。

value[0][0〜1023]
value[1][0〜1023]
...
value[15][0〜1023]

⸻

ここで大事なこと

1024 は画像の横幅ではありません。

1024 = 画素値の段階数

です。

たとえば、ある画素の値が 300 なら、

value[0][300]

を見る。

ある画素の値が 900 なら、

value[0][900]

を見る。

つまり、2つ目の [1024] は、

画素値を入れる場所

です。

⸻

かなり雑なイメージ

たとえば、こういう画像がある。

画素A = 100

画素C = 900

LUTを使うと、

画素Aは value[?][100] を見る
画素Bは value[?][300] を見る
画素Cは value[?][900] を見る

となります。

だから、LUTサイズが1024必要なのは、

たとえば4本あるなら、

状況2のとき使う表
状況3のとき使う表

元の点数 → 補正後の点数

雨の日の補正表。

元の点数 → 補正後の点数

雪の日の補正表。

元の点数 → 補正後の点数

猛暑の日の補正表。

元の点数 → 補正後の点数

このように、条件ごとに補正表を持つ。

value[4][1024] は、

4種類の条件 × 1024段階の画素値

です。

value[16][1024] は、

16種類の条件 × 1024段階の画素値

です。

⸻

12bit画像の場合はどうなる？

あなたの業務では12bitも出てきました。

12bitの画素値は、

0〜4095

です。

でもLUTサイズが1024なら、

0〜1023

までしか表がありません。

この場合は、12bitの値を10bit相当に縮めてからLUTを見ることがあります。

たとえば、

12bit値 0〜4095
↓
4で割る
↓
10bit値 0〜1023

C++なら、

index = pixelValue >> 2;

です。

例：

pixelValue = 4000
4000 / 4 = 1000
value[?][1000] を見る

⸻

なぜ4で割るのか

12bitは4096段階。

10bitは1024段階。

4096 ÷ 1024 = 4

だから、12bit値を4で割ると、10bit相当の範囲に収まります。

0     → 0
4     → 1
8     → 2
...
4092  → 1023
4095  → 1023

C++の >> 2 は、ざっくり言えば整数を4で割る操作です。

⸻

今回の話に戻す

今回の value[4][1024] は、

4本のLUTがある
各LUTは、画素値0〜1023に対応している

という意味。

大きい側の value[16][1024] は、

16本のLUTがある
各LUTは、画素値0〜1023に対応している

という意味。

だから、

4×1024
16×1024

は画像のサイズではありません。

LUTの本数 × 画素値の段階数

です。

⸻

一番大事な理解

これだけ覚えればいいです。

画素値 = 1画素の明るさの数字
段階数 = その明るさを何段階で表せるか
1024 = 0〜1023 の1024段階
LUT = 画素値ごとの補正表
value[4][1024] = 1024段階の補正表が4本
value[16][1024] = 1024段階の補正表が16本

⸻

さらに短く言うと

value[4][1024]

は、

4冊の辞書がある。
それぞれの辞書には、0〜1023番までの項目がある。

という感じです。

画素値が300なら、

300番のページを見る

条件が2番なら、

2冊目の辞書の300番を見る

つまり、

value[2][300]

です。

⸻

今のあなた向けの理解

今はこう理解すれば十分です。

1024は「画像の横幅」ではない。
1024は「画素値の種類の数」。
4や16は「補正表の本数」。
小さい側は4本。
大きい側は16本。
でも今回の実験では、大きい側も先頭4本しか使っていなさそう。
だから小さい側4本を、大きい側の先頭4本へコピーするのが自然。

これでかなり整理できます。
