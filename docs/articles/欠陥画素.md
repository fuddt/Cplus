

1. 欠陥画素テーブルの座標を、任意の座標に書き換える
2. 画像データ側の同じ座標を、わざと壊す
3. 欠陥画素補正を実行する
4. 補正前後の画像をCSVで比較する
5. その座標の値が周辺相当値に置き換わったことを確認する

これは、自然に欠陥を探すよりずっと証明しやすいです。

⸻

画像データ側を欠損させることは可能？

可能です。

画像データが配列なら、任意の座標の値を書き換えればいいです。

例えばU16画像なら、

image[y * lineSpanElements + x] = 0;

U32画像なら、

image[y * lineSpanElements + x] = 0;

です。

違うのは、lineSpanElements の計算です。

lineSpanElements = lineSpanBytes / sizeof(U16);

または、

lineSpanElements = lineSpanBytes / sizeof(U32);

⸻

U16画像で任意座標を壊す例

#include <cstdint>
using U16 = std::uint16_t;
/*
    U16画像の任意座標を、人工的な欠陥値に書き換える。
    image:
        画像データの先頭
    width / height:
        有効画像サイズ
    lineSpanBytes:
        1行あたりのbyte数
    x / y:
        壊したい座標
    defectValue:
        書き込む異常値
        例: 0, 65535
*/
bool makeArtificialDefectU16(
    U16* image,
    int width,
    int height,
    int lineSpanBytes,
    int x,
    int y,
    U16 defectValue
)
{
    if (image == nullptr)
    {
        return false;
    }
    if (x < 0 || x >= width)
    {
        return false;
    }
    if (y < 0 || y >= height)
    {
        return false;
    }
    if (lineSpanBytes % static_cast<int>(sizeof(U16)) != 0)
    {
        return false;
    }
    const int lineSpanElements =
        lineSpanBytes / static_cast<int>(sizeof(U16));
    image[y * lineSpanElements + x] = defectValue;
    return true;
}

呼び出し例：

makeArtificialDefectU16(
    image,
    3840,
    1860,
    3840 * sizeof(U16),
    100,
    200,
    0
);

証明の流れ

例えば x=100, y=200 を検証点にするなら、

1. 欠陥画素テーブルに x=100, y=200 を入れる
2. 補正前画像の image[200][100] を 0 にする
3. 補正前画像をbin/CSV出力する
4. 欠陥画素補正を実行する
5. 補正後画像をbin/CSV出力する
6. CSVで image[200][100] が周辺に近い値へ変わったことを見る

これでかなり説明できます。

⸻

注意：座標変換が必要な場合

もし小さい構造体の欠陥座標を、大きい構造体側へ移す検証なら、シェーディングと同じでYオフセットを考えます。

dstX = srcX;
dstY = srcY + dstStartY;

ここで、

dstStartY = dstHeight - srcHeight + placementOffsetY;

です。

だから、画像データ側を壊す座標も、変換後の座標 に合わせる必要があります。

例えば、

src欠陥座標:
x=100, y=200
dstStartY=790
dst画像上の欠陥座標:
x=100, y=990

なら、画像側で壊すのは、

image[990][100] = 0;

です。

ここを間違えると、

欠陥画素テーブルは x=100,y=990 を補正しようとする
でも画像側で壊したのは x=100,y=200

となって、補正されません。

⸻

端は避けた方がいい

最初の検証では、端の座標は避けてください。

悪い例：

x=0, y=0
x=3839, y=1859

端は周辺画素が足りなくて、例外処理が入る可能性があります。

最初は中央付近がいいです。

x=1000, y=1000
x=500, y=800

のような座標です。

⸻

さらに強くするなら

1点だけでなく、3点くらい作るとよいです。

点A: 左上寄り
点B: 中央
点C: 左下寄り

ただし端ギリギリは避ける。

これで、Yオフセットも含めて座標変換が正しいことを確認できます。

まとめ

欠陥画素テーブルの座標を任意の座標へ書き換える
画像データ側の同じ座標を人工的に異常値にする
補正前後をCSVで比較する

これが一番強い検証です。

重要なのは、欠陥画素テーブルの座標と、画像側で壊す座標を完全に一致させることです。
小さい→大きい変換が入るなら、画像側で壊すのは変換後の座標です。

⸻

1. 隣の画素が「同じ色」ではない

ベイヤー画像は、普通の完成画像と違って、1画素ごとに色が違います。

例えば RGGB ならこう。

R G R G
G B G B
R G R G
G B G B

つまり、ある画素が R だった場合、

* 右隣は G
* 下隣も G
* 斜めや2つ先に R

みたいになります。

これが何を意味するか

欠陥画素補正で、

周辺を平均して埋めればいい

と単純に考えると危険です。

なぜなら、色の違う画素を混ぜる可能性があるから。

⸻

2. 補正は「同じ色の近傍」を使うことが多い

例えば、欠陥画素が R の位置なら、補正には R の近傍を使う方が自然です。

イメージはこうです。

R . R
. X .
R . R

X が欠陥の R 画素なら、

* 左右2つ先
* 上下2つ先
* 斜め

みたいな 同じ色の画素 を使って補正することがあります。

だから重要なこと

補正後の値が「周辺と近い」ことを確認するときも、

上下左右1画素

だけを見るとズレることがあります。

見るべきなのは、

同じベイヤー色の近傍

です。

⸻

3. 欠陥座標の「偶数・奇数」が重要

ベイヤー画像では、x, y の偶奇で色が決まります。

RGGB の一例なら、

* (偶数, 偶数) → R
* (奇数, 偶数) → G
* (偶数, 奇数) → G
* (奇数, 奇数) → B

のようになります。

なので、欠陥画素テーブルの座標をいじるときは、

その座標が何色の画素なのか

を意識した方がいいです。

例えば

x=100, y=200 を壊したとき、その座標が R なのか G なのか B なのかで、
補正のされ方が違う可能性があります。

⸻

4. 検証用の人工欠陥は「中央付近」に置く

端は避けた方がいいです。

理由は2つ。

理由1

端だと近傍が足りない。

理由2

ベイヤー補正は、端で特別処理をしていることがある。

なので最初の検証は、例えばこういう座標がいいです。

x=100, y=100
x=200, y=300
x=500, y=500

ただし、画像サイズの中央寄りで、端から十分離す。

⸻

5. 検証画像は「なるべく均一」に近い方がいい

欠陥画素補正の確認では、周りの値がバラバラだと分かりにくいです。

例えば、周辺がこうだと分かりやすい。

1000 1000 1000
1000    0 1000
1000 1000 1000

この場合、中心が補正後に 1000 前後になれば分かりやすい。

ベイヤー画像でも有効？

有効です。
特に フラットな画像 がいいです。

例えば、

* 均一な明るさの画像
* できるだけ模様の少ない画像
* 白っぽい面、灰色面

こういう入力なら、補正前後の変化が見やすいです。

⸻

6. 補正前後比較では「対象画素だけ」を見るのでなく、近傍パッチを見る

1点だけ見ると分かりにくいです。

例えば x=100, y=200 を対象にしたら、
その周辺 5×5 や 7×7 をCSVに出して見るといいです。

ただし、ベイヤー画像では次の2つを見るといいです。

見るもの

1. 対象画素そのもの
2. 同じ色の近傍画素

⸻

7. 0 を入れる検証は有効。ただし「黒レベル」に注意

RAW/Bayer画像では、見た目の黒が必ずしも 0 とは限りません。

例えば12bit RAWなら、

* 有効範囲が 0〜4095
* でも実際は黒レベルが 64 や 256

みたいなことがあります。

だから、人工欠陥として 0 を入れるのは分かりやすいけど、

通常の暗い画素

との区別は少し意識した方がいいです。

ただ、検証としては 0 や max値 を入れるのは有効です。

⸻

8. 欠陥画素補正は、たいていデモザイク前のRAW座標でやる

ここも重要です。

今回の欠陥画素テーブルの x, y は、たぶん

完成画像のRGB座標

ではなく、

RAWベイヤー画像の座標

です。

なので、座標の意味を混同しないこと。

⸻

実務的に一番大事なポイント

あなたが今やるべきことを絞ると、これです。

⸻

最優先で考慮する点 3つ

1. 欠陥座標の色を確認する

その x, y が R/G/B のどれか。

2. 補正後の比較では「同じ色の近傍」を見る

上下左右1画素だけではなく、同色位置も見る。

3. 人工欠陥は均一画像の中央に作る

端は避ける。模様の少ない場所にする。

⸻

一番わかりやすい検証方法

例えばこうする。

手順

1. ベイヤー画像の中央付近の1点を選ぶ
2. その点の x, y を欠陥画素テーブルに登録
3. 画像データ側の同じ座標を 0 にする
4. 補正前後をbin出力
5. Pythonで周辺 7×7 をCSV化
6. 対象画素が周辺に近い値へ変わったか確認
7. できれば、その対象画素と同じ色の近傍も確認

⸻

率直に言うと

ベイヤー画像で面倒なのは、

「周辺を見ればいい」

が、そのままだと雑すぎるところです。

普通の完成画像なら周辺平均で話しやすい。
でもベイヤーでは、

同じ色の近傍か
補正がRAW座標系で走っているか

を意識しないと、見方を間違えます。

1. Bayer配列で座標が何色か判定する

まず前提として、RGGB配列ならこうです。

y=0: R G R G ...
y=1: G B G B ...
y=2: R G R G ...
y=3: G B G B ...

つまり、x と y の偶数・奇数で色が決まります。

#include <cstdint>
#include <string>
enum class BayerColor
{
    R,
    Gr,
    Gb,
    B
};
/*
    RGGB Bayer配列において、
    指定座標 x, y が何色の画素かを判定する。
    前提:
        y=0: R G R G ...
        y=1: G B G B ...
    x偶数, y偶数 -> R
    x奇数, y偶数 -> Gr
    x偶数, y奇数 -> Gb
    x奇数, y奇数 -> B
*/
BayerColor getBayerColorRGGB(int x, int y)
{
    const bool xEven = (x % 2) == 0;
    const bool yEven = (y % 2) == 0;
    if (yEven && xEven)
    {
        return BayerColor::R;
    }
    if (yEven && !xEven)
    {
        return BayerColor::Gr;
    }
    if (!yEven && xEven)
    {
        return BayerColor::Gb;
    }
    return BayerColor::B;
}
std::string toString(BayerColor color)
{
    switch (color)
    {
    case BayerColor::R:
        return "R";
    case BayerColor::Gr:
        return "Gr";
    case BayerColor::Gb:
        return "Gb";
    case BayerColor::B:
        return "B";
    }
    return "Unknown";
}

たとえば、

int x = 100;
int y = 200;
BayerColor color = getBayerColorRGGB(x, y);

なら、x=100 偶数、y=200 偶数なので、R です。

2. 画像データ側に人工欠陥を作る

画像が U16 のBayer画像だと仮定します。
指定座標を 0 や 65535 に書き換えれば、人工的に壊せます。

#include <cstdint>
using U16 = std::uint16_t;
/*
    U16 Bayer画像の任意座標を人工的に壊す。
    image:
        画像バッファ先頭
    width / height:
        有効画像サイズ
    lineSpanBytes:
        1行あたりのbyte数
    x / y:
        壊したい座標
    defectValue:
        欠陥として書き込む値
        例:
            0      -> 黒点
            65535  -> 白点
*/
bool makeArtificialDefectU16(
    U16* image,
    int width,
    int height,
    int lineSpanBytes,
    int x,
    int y,
    U16 defectValue
)
{
    if (image == nullptr)
    {
        return false;
    }
    if (x < 0 || x >= width)
    {
        return false;
    }
    if (y < 0 || y >= height)
    {
        return false;
    }
    if (lineSpanBytes % static_cast<int>(sizeof(U16)) != 0)
    {
        return false;
    }
    // byte単位のLineSpanを、U16要素数に変換する
    const int lineSpanElements =
        lineSpanBytes / static_cast<int>(sizeof(U16));
    // 2次元座標を1次元配列indexへ変換する
    const int index =
        y * lineSpanElements + x;
    image[index] = defectValue;
    return true;
}

呼び出し例。

const int x = 1000;
const int y = 1000;
makeArtificialDefectU16(
    image,
    3840,
    1860,
    3840 * sizeof(U16),
    x,
    y,
    0
);

3. 欠陥画素テーブルに同じ座標を登録する

構造体は仮でこう置きます。

#include <cstdint>
#include <algorithm>
using U16 = std::uint16_t;
struct DefectivePixel
{
    U16 x;
    U16 y;
};
struct DefectiveTable
{
    U16 count;
    DefectivePixel table[200];
};
/*
    欠陥画素テーブルに1点だけ登録する。
    検証では、まず1点だけに絞る方がよい。
    いきなり複数点にすると、どの補正が効いたのか追いにくい。
*/
bool setOneDefectivePixel(
    DefectiveTable& defectiveTable,
    U16 x,
    U16 y
)
{
    defectiveTable.count = 1;
    defectiveTable.table[0].x = x;
    defectiveTable.table[0].y = y;
    // 未使用領域を無効値で埋める。
    // 実際の仕様が count を見るなら不要だが、
    // 固定長を全部読む可能性があるなら重要。
    for (int i = 1; i < 200; ++i)
    {
        defectiveTable.table[i].x = 0xFFFF;
        defectiveTable.table[i].y = 0xFFFF;
    }
    return true;
}

検証の流れはこうです。

const U16 x = 1000;
const U16 y = 1000;
// 1. 欠陥画素テーブルに登録
setOneDefectivePixel(defectiveTable, x, y);
// 2. 画像データ側の同じ座標を壊す
makeArtificialDefectU16(
    image,
    3840,
    1860,
    3840 * sizeof(U16),
    x,
    y,
    0
);

4. 小さい画像から大きい画像へ座標変換する場合

シェーディング補正で見つけたYオフセットがあるなら、欠陥画素座標も同じ発想で変換します。

dstX = srcX
dstY = srcY + dstStartY
dstStartY = dstHeight - srcHeight + placementOffsetY

コードにするとこうです。

struct DefectiveTableSmall
{
    U16 count;
    DefectivePixel table[200];
};
struct DefectiveTableLarge
{
    U16 count;
    DefectivePixel table[500];
};
/*
    小さい画像用の欠陥画素座標を、
    大きい画像用の欠陥画素座標へ変換する。
    左下配置 + Yオフセットあり。
*/
bool convertDefectiveTableToLarge(
    const DefectiveTableSmall& src,
    DefectiveTableLarge& dst,
    int srcWidth,
    int srcHeight,
    int dstWidth,
    int dstHeight,
    int placementOffsetY
)
{
    dst.count = 0;
    const int dstStartY =
        dstHeight - srcHeight + placementOffsetY;
    if (dstStartY < 0)
    {
        return false;
    }
    if (dstStartY + srcHeight > dstHeight)
    {
        return false;
    }
    const int srcCount =
        std::min<int>(src.count, 200);
    for (int i = 0; i < srcCount; ++i)
    {
        const int srcX = src.table[i].x;
        const int srcY = src.table[i].y;
        // 無効値をスキップ
        if (srcX == 0xFFFF || srcY == 0xFFFF)
        {
            continue;
        }
        // 小さい画像範囲外はスキップ
        if (srcX < 0 || srcX >= srcWidth)
        {
            continue;
        }
        if (srcY < 0 || srcY >= srcHeight)
        {
            continue;
        }
        const int dstX = srcX;
        const int dstY = srcY + dstStartY;
        // 大きい画像範囲外はスキップ
        if (dstX < 0 || dstX >= dstWidth)
        {
            continue;
        }
        if (dstY < 0 || dstY >= dstHeight)
        {
            continue;
        }
        if (dst.count >= 500)
        {
            return false;
        }
        dst.table[dst.count].x = static_cast<U16>(dstX);
        dst.table[dst.count].y = static_cast<U16>(dstY);
        ++dst.count;
    }
    // 未使用領域を無効値で埋める
    for (int i = dst.count; i < 500; ++i)
    {
        dst.table[i].x = 0xFFFF;
        dst.table[i].y = 0xFFFF;
    }
    return true;
}

この場合、画像側に人工欠陥を作る座標も 変換後座標 に合わせます。

const int srcX = 1000;
const int srcY = 1000;
const int dstStartY =
    dstHeight - srcHeight + placementOffsetY;

const int dstY = srcY + dstStartY;
// 大きい画像側のこの座標を人工的に壊す

U16画像を想定します。

import numpy as np
WIDTH = 3840
HEIGHT = 1860
TARGET_X = 1000
TARGET_Y = 1000
RADIUS = 4

after  = np.fromfile("after_defect.bin", dtype=np.uint16).reshape(HEIGHT, WIDTH)
y0 = TARGET_Y - RADIUS
y1 = TARGET_Y + RADIUS + 1
x0 = TARGET_X - RADIUS
x1 = TARGET_X + RADIUS + 1
before_patch = before[y0:y1, x0:x1]

np.savetxt("before_patch.csv", before_patch, fmt="%d", delimiter=",")

np.savetxt("diff_patch.csv", diff_patch, fmt="%d", delimiter=",")

def bayer_color_rggb(x: int, y: int) -> str:
    """
    RGGB配列で、指定座標が何色か返す。
    y=0: R G R G ...
    y=1: G B G B ...
    """
    if y % 2 == 0 and x % 2 == 0:
        return "R"
    if y % 2 == 0 and x % 2 == 1:
        return "Gr"
    if y % 2 == 1 and x % 2 == 0:
        return "Gb"
    return "B"

7. 同じ色の近傍を見るPythonコード

欠陥画素補正がBayerを考慮している場合、上下左右1画素ではなく、同じ色の近傍を見る方が自然です。

import numpy as np
def same_color_neighbors_2px(img: np.ndarray, x: int, y: int):
    """
    Bayer画像で同じ色になりやすい2px離れた近傍を取得する。
    RGGBなどの2x2周期では、
    x方向・y方向に2つ離れると同じ色になる。
    """
    h, w = img.shape
    points = [
        (x - 2, y),
        (x + 2, y),
        (x, y - 2),
        (x, y + 2),
    ]
    values = []
    for px, py in points:
        if 0 <= px < w and 0 <= py < h:
            values.append(int(img[py, px]))
    return values
before_neighbors = same_color_neighbors_2px(before, TARGET_X, TARGET_Y)
after_neighbors  = same_color_neighbors_2px(after, TARGET_X, TARGET_Y)
print("target color =", bayer_color_rggb(TARGET_X, TARGET_Y))
print("same color neighbors before =", before_neighbors)
print("same color neighbors after  =", after_neighbors)
if before_neighbors:
    print("same color neighbor mean before =", sum(before_neighbors) / len(before_neighbors))

10. 重要なまとめ

ベイヤー画像で考慮すべきことはこれです。

1. 欠陥座標のx,yからBayer色を確認する
2. 補正後値は上下左右1画素ではなく、同じ色の近傍と比較する
3. 人工欠陥は端ではなく中央付近に作る
4. 小さい→大きい変換があるなら、欠陥座標もYオフセット込みで変換する
5. 画像側で壊す座標と、欠陥画素テーブルに登録する座標を必ず一致させる

ここまでやれば、欠陥画素補正の証明としてかなり強いです。
