# インスタンスの破棄とデストラクタ

C++ では、クラスのインスタンスが破棄されるとき、**デストラクタ**が自動的に呼ばれる。  
「作るときにコンストラクタが走る」のと対になる仕組みだ。

この記事では、インスタンスがいつ・どのように破棄されるか、  
そしてデストラクタで何をすべきか・すべきでないかを整理する。

---

## 第1章：デストラクタの基本

デストラクタはクラス名の前に `~` をつけた特殊なメンバ関数だ。

```cpp
class MyClass
{
public:
    MyClass()  { /* 初期化 */ }
    ~MyClass() { /* 後片付け */ }
};
```

- 引数を取れない
- 戻り値を持てない
- オーバーロードできない（1クラスにひとつだけ）

何も書かなければ、コンパイラが何もしないデストラクタを自動生成する。

---

## 第2章：いつ呼ばれるか

インスタンスの破棄タイミングは、**生存期間（ライフタイム）** によって決まる。

### 2-1. ローカル変数：スコープを抜けたとき

```cpp
void example()
{
    MyClass obj;   // コンストラクタが呼ばれる
    // ... 処理 ...
}                  // ここで自動的にデストラクタが呼ばれる
```

`{` と `}` で囲まれたスコープを抜けた瞬間に破棄される。  
`return` や `throw` で途中を抜けた場合も、スコープ内のすべてのローカル変数が破棄される。

### 2-2. `new` で生成したとき：`delete` を呼んだとき

```cpp
MyClass* obj = new MyClass();  // コンストラクタが呼ばれる
// ... 処理 ...
delete obj;                    // デストラクタが呼ばれ、メモリが解放される
obj = nullptr;                 // ポインタをnullptrにしておくと安全
```

`delete` を呼ばなければデストラクタは走らず、メモリリークになる。  
これが `new` / `delete` を手動管理する場合の主なリスクだ。

### 2-3. スタック上の複数変数：逆順に破棄される

```cpp
void example()
{
    MyClass a;  // 1番目に構築
    MyClass b;  // 2番目に構築
    MyClass c;  // 3番目に構築
}
// c → b → a の順で破棄される（構築と逆順）
```

## 第3章：スマートポインタを使うと `delete` が不要になる

C++11 以降は `std::unique_ptr` / `std::shared_ptr` を使うのが標準的だ。  
スコープを抜けると自動で `delete` が呼ばれるため、手動管理が不要になる。

```cpp
#include <memory>

void example()
{
    auto obj = std::make_unique<MyClass>();  // new の代わり
    // ... 処理 ...
}  // ここで自動的に delete される。明示的な delete は不要
```

`unique_ptr` はひとつのオブジェクトをひとりの所有者が管理する。  
`shared_ptr` は複数の所有者で共有でき、最後の所有者がいなくなった時点で破棄される。

```cpp
#include <memory>

void example()
{
    auto a = std::make_shared<MyClass>();
    auto b = a;  // a と b で同じオブジェクトを共有
    // b がなくなっても a が生きている間は破棄されない
}  // a も b もスコープを抜けたとき、初めて破棄される
```

## 第4章：デストラクタで何をするか

デストラクタの役割は**後片付け**だ。コンストラクタで確保したリソースを解放する。

```cpp
#include <iostream>

class FileHandle
{
public:
    FileHandle(const char* path)
    {
        file_ = fopen(path, "r");
    }

    ~FileHandle()
    {
        if (file_ != nullptr)
        {
            fclose(file_);  // コンストラクタで開いたファイルを閉じる
        }
    }

private:
    FILE* file_ = nullptr;
};
```

`FileHandle` を使う側はファイルのクローズを気にしなくてよい。  
スコープを抜ければ自動で閉じられる。

この「コンストラクタで取得、デストラクタで解放」というパターンを **RAII** という。  
（Resource Acquisition Is Initialization）

---

## 第5章：デストラクタで例外を投げてはいけない

デストラクタ内で例外を投げると、プログラムが `std::terminate` で強制終了する可能性がある。

```cpp
~MyClass()
{
    throw std::runtime_error("error");  // 危険。絶対にやってはいけない
}
```

デストラクタはエラーが起きている最中（例外処理中）にも呼ばれることがある。  
そのタイミングでさらに例外を投げると、C++ の仕様上プログラムが終了する。

デストラクタ内でエラーが起きても、例外は投げずに握りつぶすか、ログに記録するだけにとどめる。

---

## 第6章：継承があるときは仮想デストラクタが必要

基底クラスのポインタ経由でオブジェクトを delete するとき、  
基底クラスのデストラクタが `virtual` でないと**派生クラスのデストラクタが呼ばれない**。

```cpp
class Base
{
public:
    ~Base() { /* 派生クラスのデストラクタは呼ばれない */ }
};

class Derived : public Base
{
public:
    ~Derived() { /* ここが呼ばれない！ */ }
};

Base* obj = new Derived();
delete obj;  // Derived のデストラクタがスキップされる → リソースリーク
```

基底クラスのデストラクタを `virtual` にすることで解決する。

```cpp
class Base
{
public:
    virtual ~Base() = default;  // virtual をつける
};

class Derived : public Base
{
public:
    ~Derived() { /* 正しく呼ばれる */ }
};

Base* obj = new Derived();
delete obj;  // Derived → Base の順で正しく破棄される
```

**継承を想定するクラスには、必ず `virtual ~ClassName() = default;` を書く。**

---

## 判断基準まとめ

| 状況 | 対応 |
| :--- | :--- |
| ローカル変数 | スコープを抜けると自動破棄。何もしなくていい |
| `new` で生成 | 対応する `delete` を必ず呼ぶ |
| `new` で生成（モダンC++） | `std::unique_ptr` / `std::shared_ptr` を使い `delete` を不要にする |
| コンストラクタでリソース確保 | デストラクタで解放する（RAII） |
| 継承を想定するクラス | `virtual ~ClassName() = default;` を書く |
| デストラクタ内のエラー | 例外を投げない |

## 理解度チェック

次のコードで問題のある箇所はどこか。

```cpp
class Buffer
{
public:
    Buffer(int size)
    {
        data_ = new int[size];
    }

private:
    int* data_;
};

void example()
{
    Buffer buf(100);
}
```

**問題点と修正：**

1. **デストラクタがない** → `data_` で確保したメモリが解放されずリークする
2. **修正方法A**：デストラクタを書いて `delete[] data_` を呼ぶ
3. **修正方法B**：`data_` を `std::unique_ptr<int[]>` にする（デストラクタ不要になる）

```cpp
// 修正方法B（推奨）
#include <memory>

class Buffer
{
public:
    Buffer(int size) : data_(std::make_unique<int[]>(size)) {}

private:
    std::unique_ptr<int[]> data_;
};
```

> **ポイント：** スマートポインタを使うと、メンバの解放もデストラクタも自動化できる。  
> 手動で `new` / `delete` を書く場面は、現代のC++では非常に限られている。
