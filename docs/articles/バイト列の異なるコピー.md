パターン1: U16 → U16 (4×1024 → 16×1024)

これは型が同じなので memcpy が使えます。

#include <cstring>
uint16_t src[4][1024];
uint16_t dst[16][1024];
// 全部0埋め
memset(dst, 0, sizeof(dst));
// 先頭4行だけコピー
memcpy(
    dst,
    src,
    sizeof(src)
);

イメージ

src
Row0  ← コピー
Row1  ← コピー
Row2  ← コピー
Row3  ← コピー
↓
dst
Row0 ← src Row0
Row1 ← src Row1
Row2 ← src Row2
Row3 ← src Row3
Row4 ← 0
...
Row15 ← 0

出力するなら

fwrite(
    dst,
    sizeof(uint16_t),
    16 * 1024,
    fp
);

Python側

arr = np.fromfile(
    path,
    dtype=np.uint16
).reshape(16, 1024)

パターン2: U16 → U08 (4×1024 → 16×1024)

これは型変換が必要なので memcpy は不可です。

uint16_t src[4][1024];
uint8_t dst[16][1024];
memset(dst, 0, sizeof(dst));
for (int y = 0; y < 4; y++)
{
    for (int x = 0; x < 1024; x++)
    {
        dst[y][x] =
            static_cast<uint8_t>(src[y][x]);
    }
}

出力

fwrite(
    dst,
    sizeof(uint8_t),
    16 * 1024,
    fp
);

Python

arr = np.fromfile(
    path,
    dtype=np.uint8
).reshape(16, 1024)

⸻

パターン3: memcpyで無理やりU16→U08

これはたぶん今回起きている現象です。

uint16_t src[4][1024];
uint8_t dst[16][1024];
memcpy(
    dst,
    src,
    sizeof(src)
);

sizeof(src) は

4 × 1024 × 2
=
8192 byte

です。

つまり

U16 1個
↓
U08 2個

としてコピーされます。

例えば

src[0][0] = 0x1234;

なら

34 12

が書かれます。

Pythonで見ると

1行目 ← 下位バイト群
2行目 ← 上位バイト群
3行目 ← 次の行の下位バイト群
4行目 ← 次の行の上位バイト群
...

となります。

あなたの

小さいやつの1行目
小さいやつの1行目
小さいやつの2行目
小さいやつの2行目

という現象は、このパターンとかなり一致しています。

⸻

fwrite(
    data,

    ...,
    fp
);

の行です。

ここで

* data の型
* sizeof(...)
* 第3引数

を見れば、ほぼ原因を特定できます。今の症状だと「U16で保持しているのに、PythonでU08として読んでいる」可能性が最も高いです。
