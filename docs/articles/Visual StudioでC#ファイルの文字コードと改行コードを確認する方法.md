# Visual StudioでC#ファイルの文字コードと改行コードを確認する方法

「.csファイルはUTF-8(BOM)、改行はWindows(CRLF)で揃えてください」という指示を
受けたとき、それを確認する手段が分からない、ということがある。ここでは
Visual Studioだけでこれを確認する方法をまとめる。

今回のような指示は、要するに`.cs`ファイルを次の状態に統一してほしい、という意味。

- 文字コード：UTF-8 BOM付き
- 改行コード：CRLF（Windows）

## 簡易確認：エディタ右下の表示

Visual Studio 2022では、エディタ右下に現在の**Encoding**と**Line endings**が
表示される。例えば右下が

```
CRLF   UTF-8
```

のように見える。ただし、この表示だけでは**BOM付きかどうかまでは判別しづらい**
場合がある。確実に確認したいときは次の方法を使う。

## 確実な確認方法：「エンコード付きで保存」ダイアログ

1. 対象の`.cs`ファイルを開く
2. `[ファイル]` → `[○○.cs に名前を付けて保存]`
3. 保存ダイアログの`[保存]`ボタン右側の▼を押して、`[エンコード付きで保存]`を選ぶ
4. 「保存オプションの詳細設定」ダイアログが開き、現在のエンコードと改行コードが
   表示される

ここで次のように表示されていれば、指示どおりの状態。

```
エンコード: Unicode (UTF-8 with signature) - Codepage 65001
行末:       Windows (CR LF)
```

**ファイルを変更せず確認だけしたい場合は、保存を確定せずダイアログを閉じればよい**。
この手順は非破壊的に使える。

Visual Studio 2019では2022と表示・手順が多少異なるため、必要であれば別途確認する。

## 判定基準

| 指示 | Visual Studio上での表示 |
|---|---|
| UTF8(BOM) | `Unicode (UTF-8 with signature) - Codepage 65001` |
| 改行はWin | `Windows (CR LF)` |

ポイントは **"with signature"** の部分。Visual Studioではこれが「BOMあり」を
意味する。

```
UTF-8 with signature
        ↓
UTF-8 BOMあり
```

逆に`UTF-8 without signature`と表示された場合はBOMなしなので、今回の指示には
合わない。

## 恒久的な統一策：.editorconfig

ファイルを1つずつ人力で確認する運用は、チーム開発では取りこぼしが起きやすい。
`.editorconfig`をリポジトリに置いて、文字コードと改行コードをプロジェクト単位で
固定しておく方が安全。

```ini
[*.cs]
# UTF-8 BOM付き
charset = utf-8-bom
# Windows改行
end_of_line = crlf
```

これを置いておけば、Visual Studio側が新規作成・保存時にこのルールをある程度
自動的に守ってくれる。ただし、**ルール導入前から存在する既存ファイルまでは
自動的に直してくれるわけではない**ため、既存ファイルの点検には上記の
「エンコード付きで保存」ダイアログでの確認が引き続き必要になる。

## まとめ

- 既存ファイルの点検は「名前を付けて保存」→「エンコード付きで保存」で、
  ファイルを変更せずに確認できる
- 今後の統一は`.editorconfig`に任せる方が、毎回人力で確認するより安全
