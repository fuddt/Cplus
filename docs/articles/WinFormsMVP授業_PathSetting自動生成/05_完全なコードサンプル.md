# Part5. 完全なコードサンプル

Part1〜4で議論した設計を、実際に動く一つのコード一式としてまとめる。断片ではなく、上から順にコピーしていけば意味が繋がるように構成している。

対象はPathSetting側（FolderA〜Eの自動生成・相関検証）のみ。GenerateForm側（`GeneratePresenter`など）は今回のシリーズの主題外なので、末尾で軽く触れるだけに留める。

## ファイル構成

```text
PathType.cs                    … B/C/D/Eを区別する列挙型
PathGenerationStatus.cs        … 生成状態を表す列挙型（Part1）
PathGenerationResult.cs        … 生成結果の値オブジェクト
PathGenerationItem.cs          … 1フォルダ分の入力値・生成結果・状態（Part1, Part4）
PathSettingModel.cs            … A〜Eをまとめて保持する共有Model
IFilePathGenerationService.cs  … パス生成だけを行うService（Part3）
IPathSettingEvaluator.cs       … A〜Eの依存関係を判定するEvaluator（Part3, Part4）
ValidationResult.cs            … 相関検証の結果
IFileValidationService.cs      … 件数一致・カラム名一致の検証Service
IPathSettingView.cs            … View抽象
PathSettingForm.cs             … UserControl実装
PathSettingPresenter.cs        … ViewとEvaluator/Validatorをつなぐ
```

## PathGenerationStatus（Part1）

```csharp
public enum PathGenerationStatus
{
    NotEntered,   // 対象フォルダが未入力
    WaitingForA,  // Aが未入力/無効なので待機中
    Success,      // 生成成功
    InvalidInput, // 入力値が不正
    Failed        // 生成処理で失敗
}
```

## PathGenerationResult

`IFilePathGenerationService`の戻り値。生成できた場合／できなかった場合を、ファクトリメソッドで作りやすくしている。

```csharp
public class PathGenerationResult
{
    public string FilePath { get; }
    public PathGenerationStatus Status { get; }
    public string Message { get; }

    private PathGenerationResult(string filePath, PathGenerationStatus status, string message)
    {
        FilePath = filePath;
        Status = status;
        Message = message;
    }

    public static PathGenerationResult Success(string filePath) =>
        new PathGenerationResult(filePath, PathGenerationStatus.Success, string.Empty);

    public static PathGenerationResult Invalid(string message) =>
        new PathGenerationResult(string.Empty, PathGenerationStatus.InvalidInput, message);

    public static PathGenerationResult Failed(string message) =>
        new PathGenerationResult(string.Empty, PathGenerationStatus.Failed, message);
}
```

## PathGenerationItem（Part1, Part4）

`Status`・`GeneratedFilePath`・`Message`は`private set`にし、専用メソッド経由でしか変更できないようにする。これにより「Successなのに生成結果が空」のような矛盾状態を外部から作れなくしている（Tell, Don't Ask）。

```csharp
public class PathGenerationItem
{
    public string FolderPath { get; set; } = string.Empty;
    public string GeneratedFilePath { get; private set; } = string.Empty;
    public PathGenerationStatus Status { get; private set; } = PathGenerationStatus.NotEntered;
    public string Message { get; private set; } = string.Empty;

    public void SetNotEntered()
    {
        GeneratedFilePath = string.Empty;
        Status = PathGenerationStatus.NotEntered;
        Message = string.Empty;
    }

    public void SetWaitingForA(string message)
    {
        GeneratedFilePath = string.Empty;
        Status = PathGenerationStatus.WaitingForA;
        Message = message;
    }

    public void Apply(PathGenerationResult result)
    {
        GeneratedFilePath = result.FilePath;
        Status = result.Status;
        Message = result.Message;
    }
}
```

## IFilePathGenerationService / FilePathGenerationService（Part3）

A〜Eの依存関係は一切知らない。「2つの文字列から1本のパスを組み立てる」ことだけに専念する。

```csharp
public interface IFilePathGenerationService
{
    PathGenerationResult GenerateA(string folderPath);
    PathGenerationResult GenerateDependent(string folderPathA, string dependentFolderPath, PathType pathType);
}

public class FilePathGenerationService : IFilePathGenerationService
{
    public PathGenerationResult GenerateA(string folderPath)
    {
        try
        {
            var filePath = Path.Combine(folderPath, "a-data.csv");
            return PathGenerationResult.Success(filePath);
        }
        catch (ArgumentException ex)
        {
            return PathGenerationResult.Invalid(ex.Message);
        }
    }

    public PathGenerationResult GenerateDependent(string folderPathA, string dependentFolderPath, PathType pathType)
    {
        try
        {
            var fileName = GetFileName(pathType);
            var filePath = Path.Combine(folderPathA, dependentFolderPath, fileName);
            return PathGenerationResult.Success(filePath);
        }
        catch (ArgumentException ex)
        {
            return PathGenerationResult.Invalid(ex.Message);
        }
    }

    private static string GetFileName(PathType pathType) => pathType switch
    {
        PathType.B => "b-data.csv",
        PathType.C => "c-data.csv",
        PathType.D => "d-data.csv",
        PathType.E => "e-data.csv",
        _ => throw new ArgumentOutOfRangeException(nameof(pathType))
    };
}
```

## IPathSettingEvaluator / PathSettingEvaluator（Part3, Part4）

A〜Eの依存関係（「AがSuccessでなければB〜EはWaitingForA」）を判定する。実際のパス組み立ては`IFilePathGenerationService`に委譲する。`Recalculate`は毎回A〜E全体を評価するが、未入力の項目に生成処理は呼ばない（Part2）。

```csharp
public interface IPathSettingEvaluator
{
    void Recalculate(PathSettingModel model);
}

public class PathSettingEvaluator : IPathSettingEvaluator
{
    private readonly IFilePathGenerationService _generationService;

    public PathSettingEvaluator(IFilePathGenerationService generationService)
    {
        _generationService = generationService;
    }

    public void Recalculate(PathSettingModel model)
    {
        EvaluateA(model.A);

        EvaluateDependent(model.A, model.B, PathType.B);
        EvaluateDependent(model.A, model.C, PathType.C);
        EvaluateDependent(model.A, model.D, PathType.D);
        EvaluateDependent(model.A, model.E, PathType.E);
    }

    private void EvaluateA(PathGenerationItem itemA)
    {
        if (string.IsNullOrWhiteSpace(itemA.FolderPath))
        {
            itemA.SetNotEntered();
            return;
        }

        var result = _generationService.GenerateA(itemA.FolderPath);
        itemA.Apply(result);
    }

    private void EvaluateDependent(PathGenerationItem itemA, PathGenerationItem dependent, PathType pathType)
    {
        if (string.IsNullOrWhiteSpace(dependent.FolderPath))
        {
            dependent.SetNotEntered();
            return;
        }

        if (itemA.Status != PathGenerationStatus.Success)
        {
            dependent.SetWaitingForA("フォルダパスAの入力を待っています。");
            return;
        }

        var result = _generationService.GenerateDependent(itemA.FolderPath, dependent.FolderPath, pathType);
        dependent.Apply(result);
    }
}
```

## ValidationResult / IFileValidationService / FileValidationService

FolderA/Bの件数一致、FolderB/Dのカラム名一致を検証する。生の`FolderPath`ではなく、`Status == Success`になった後の`GeneratedFilePath`を対象にする点に注意。

```csharp
public class ValidationResult
{
    public bool IsValid { get; }
    public string ErrorMessage { get; }

    private ValidationResult(bool isValid, string errorMessage)
    {
        IsValid = isValid;
        ErrorMessage = errorMessage;
    }

    public static ValidationResult Ok() => new ValidationResult(true, string.Empty);
    public static ValidationResult Ng(string message) => new ValidationResult(false, message);
}

public interface IFileValidationService
{
    ValidationResult ValidateRecordCount(string pathA, string pathB);
    ValidationResult ValidateColumnNames(string pathB, string pathD);
}

public class FileValidationService : IFileValidationService
{
    public ValidationResult ValidateRecordCount(string pathA, string pathB)
    {
        var countA = File.ReadLines(pathA).Count();
        var countB = File.ReadLines(pathB).Count();

        return countA == countB
            ? ValidationResult.Ok()
            : ValidationResult.Ng($"件数が一致しません（A:{countA}件 / B:{countB}件）");
    }

    public ValidationResult ValidateColumnNames(string pathB, string pathD)
    {
        var headerB = File.ReadLines(pathB).First();
        var headerD = File.ReadLines(pathD).First();

        return headerB == headerD
            ? ValidationResult.Ok()
            : ValidationResult.Ng("カラム名が一致しません");
    }
}
```

## PathSettingForm（UserControl実装）

TextBoxの`Leave`イベントをまとめて`FolderPathChanged`に変換するだけで、業務ロジックは一切持たない。

```csharp
public partial class PathSettingForm : UserControl, IPathSettingView
{
    // デザイナーで配置するコントロール（フィールド名は例）
    private TextBox txtFolderA = null!;
    private TextBox txtFolderB = null!;
    private TextBox txtFolderC = null!;
    private TextBox txtFolderD = null!;
    private TextBox txtFolderE = null!;
    private Label lblStatusA = null!;
    private Label lblStatusB = null!;
    private Label lblStatusC = null!;
    private Label lblStatusD = null!;
    private Label lblStatusE = null!;
    private Label lblErrorAB = null!;
    private Label lblErrorBD = null!;

    public event EventHandler? FolderPathChanged;

    public PathSettingForm()
    {
        InitializeComponent();

        txtFolderA.Leave += RaiseFolderPathChanged;
        txtFolderB.Leave += RaiseFolderPathChanged;
        txtFolderC.Leave += RaiseFolderPathChanged;
        txtFolderD.Leave += RaiseFolderPathChanged;
        txtFolderE.Leave += RaiseFolderPathChanged;
    }

    public string FolderPathA => txtFolderA.Text;
    public string FolderPathB => txtFolderB.Text;
    public string FolderPathC => txtFolderC.Text;
    public string FolderPathD => txtFolderD.Text;
    public string FolderPathE => txtFolderE.Text;

    public void ShowState(PathSettingModel model)
    {
        lblStatusA.Text = ToStatusText(model.A);
        lblStatusB.Text = ToStatusText(model.B);
        lblStatusC.Text = ToStatusText(model.C);
        lblStatusD.Text = ToStatusText(model.D);
        lblStatusE.Text = ToStatusText(model.E);
    }

    public void ShowError(FieldPair pair, string message)
    {
        var label = GetErrorLabel(pair);
        label.Text = message;
        label.ForeColor = Color.Red;
    }

    public void ClearError(FieldPair pair)
    {
        GetErrorLabel(pair).Text = string.Empty;
    }

    private void RaiseFolderPathChanged(object? sender, EventArgs e) =>
        FolderPathChanged?.Invoke(this, EventArgs.Empty);

    private Label GetErrorLabel(FieldPair pair) => pair == FieldPair.AB ? lblErrorAB : lblErrorBD;

    private static string ToStatusText(PathGenerationItem item) => item.Status switch
    {
        PathGenerationStatus.NotEntered => string.Empty,
        PathGenerationStatus.WaitingForA => "A待ち",
        PathGenerationStatus.Success => "生成済み",
        PathGenerationStatus.InvalidInput => $"入力不正：{item.Message}",
        PathGenerationStatus.Failed => $"生成失敗：{item.Message}",
        _ => "不明"
    };
}
```

## PathSettingPresenter

Viewの`FolderPathChanged`イベントを購読し、「Modelへ反映 → Evaluatorで再評価 → 検証 → Viewへ反映」という一連の流れをまとめる。

```csharp
public class PathSettingPresenter
{
    private readonly IPathSettingView _view;
    private readonly PathSettingModel _model;
    private readonly IPathSettingEvaluator _evaluator;
    private readonly IFileValidationService _validator;

    public PathSettingPresenter(
        IPathSettingView view,
        PathSettingModel model,
        IPathSettingEvaluator evaluator,
        IFileValidationService validator)
    {
        _view = view;
        _model = model;
        _evaluator = evaluator;
        _validator = validator;

        _view.FolderPathChanged += (s, e) => OnFolderPathChanged();
    }

    private void OnFolderPathChanged()
    {
        _model.A.FolderPath = _view.FolderPathA;
        _model.B.FolderPath = _view.FolderPathB;
        _model.C.FolderPath = _view.FolderPathC;
        _model.D.FolderPath = _view.FolderPathD;
        _model.E.FolderPath = _view.FolderPathE;

        _evaluator.Recalculate(_model);

        RunValidation(FieldPair.AB, _model.A, _model.B);
        RunValidation(FieldPair.BD, _model.B, _model.D);

        _view.ShowState(_model);
    }

    private void RunValidation(FieldPair pair, PathGenerationItem left, PathGenerationItem right)
    {
        if (left.Status != PathGenerationStatus.Success || right.Status != PathGenerationStatus.Success)
        {
            _view.ClearError(pair);
            return;
        }

        var result = pair == FieldPair.AB
            ? _validator.ValidateRecordCount(left.GeneratedFilePath, right.GeneratedFilePath)
            : _validator.ValidateColumnNames(left.GeneratedFilePath, right.GeneratedFilePath);

        if (result.IsValid)
        {
            _view.ClearError(pair);
        }
        else
        {
            _view.ShowError(pair, result.ErrorMessage);
        }
    }
}
```

## 動作イメージ（WinForms無しで確認する場合）

`PathSettingModel`と`PathSettingEvaluator`はWinFormsに一切依存していないので、コンソールアプリでも動作を確認できる。Part2で扱った「B→D→Aの順で入力する」というシナリオを、そのまま検証してみる。

```csharp
var model = new PathSettingModel();
var evaluator = new PathSettingEvaluator(new FilePathGenerationService());

model.B.FolderPath = "FolderB";
evaluator.Recalculate(model);
Console.WriteLine($"B: {model.B.Status} / {model.B.Message}");
// B: WaitingForA / フォルダパスAの入力を待っています。

model.D.FolderPath = "FolderD";
evaluator.Recalculate(model);
Console.WriteLine($"D: {model.D.Status} / {model.D.Message}");
// D: WaitingForA / フォルダパスAの入力を待っています。

model.A.FolderPath = @"C:\Root";
evaluator.Recalculate(model);
Console.WriteLine($"A: {model.A.Status} -> {model.A.GeneratedFilePath}");
Console.WriteLine($"B: {model.B.Status} -> {model.B.GeneratedFilePath}");
Console.WriteLine($"D: {model.D.Status} -> {model.D.GeneratedFilePath}");
// A: Success -> C:\Root\a-data.csv
// B: Success -> C:\Root\FolderB\b-data.csv
// D: Success -> C:\Root\FolderD\d-data.csv
```

Aを最後に入力しても、既に入力済みだったBとDが自動的に`Success`へ切り替わっていることが確認できる。これがPart2で目指した「入力順に依存しない」挙動そのものである。
