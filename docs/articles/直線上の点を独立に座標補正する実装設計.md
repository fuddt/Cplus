# 直線上の点を独立に座標補正する実装設計

## 目的と前提

画面上の各点には、次の 2 つがあるとする。

- 変更前の基準直線 `L0` に対する位置
- その点だけが動ける移動可能ルート `R`

基準直線を `L0` から `L1` へ動かしたとき、点 `P` を **自分のルート `R` 上だけ** で移動し、`L0` からの垂直距離をできるだけ保つ新しい点 `Q` を求める。

重要なのは、これは「点群全体の形をきれいにする」最適化ではないことだ。点 1 の答えは点 2 の座標、点間距離、全体の重なりに依存しない。各点について同じ計算を独立に一回ずつ行う。

```text
点 P1 + ルート R1  ──>  Q1
点 P2 + ルート R2  ──>  Q2
点 P3 + ルート R3  ──>  Q3

P1/P2/P3 同士を比較したり、まとめて移動量を最小化したりしない
```

このリポジトリを確認した時点では、`src/CalibrationBin/CalibrationBin.h` にある既存の `CalibrationBin::Point` と、倍率・オフセットによる `applyCalibration` はある。一方で、直線、直線同士の交点、点から直線への距離、移動可能ルートを表す既存 API はない。そのため、既存の幾何計算を重複実装する変更はせず、本記事では導入時の最小 API と実装方針を示す。

## 何を最小化するか

まず変更前の点 `P` と元の基準直線 `L0` の距離を記録する。

```text
d0 = distance(P, L0)
```

ここで使うのは符号付き距離ではなく絶対距離である。つまり `L0` の片側に 5 離れていた点は、移動後に反対側へ回っても、距離が 5 なら同じだけ良い。

候補 `Q` の評価値は次の辞書式優先順位で決める。

```text
第1優先: error(Q) = abs(distance(Q, L1) - d0) を最小化する
第2優先: error が epsilon の範囲で同じなら length(Q - P) を最小化する
```

`L1` から距離 `d0` の場所は、`L1` の両側に 1 本ずつある平行線で表せる。よって、無限直線のルートなら、総当たりではなくその 2 本との交点を計算すればよい。

```text
距離 d0 の平行線       ─────────────────
                                  / R
                               ● Q(+)
                                /
移動後の基準直線 L1     ═══════/═══════════
                             ● Q(-)
                            /
距離 d0 の平行線       ─────────────────
```

`Q(+)` と `Q(-)` はどちらも `error = 0` である。両方が有効なら、元の点 `P` から近い方を採用する。

## 直線は一般形で持つ

傾き切片形式 `y = ax + b` は、垂直線で傾きが定義できない。内部計算には次の一般形を使うと、水平線・垂直線を特別扱いせずに済む。

```text
Ax + By + C = 0
```

`A` と `B` が同時に 0 の値は直線ではないため、生成時に拒否する。以下は導入用の最小データ型である。既存プロジェクトへ正式導入するときは、既存の `CalibrationBin::Point` を再利用できる。

```cpp
struct Point {
    double x;
    double y;
};

struct Line {
    double a; // Ax + By + C = 0
    double b;
    double c;
};

struct RouteLine {
    Point origin;    // ルート上の一点。通常は元の P を渡す
    Point direction; // (dx, dy)。(0, 0) は不正
};
```

`RouteLine` は `origin + t * direction`（`t` は任意の実数）で表す。方向ベクトルを正規化する必要はない。

## 基本となる計算式

点 `(x, y)` と直線 `Ax + By + C = 0` の垂直距離は次の式で求める。

```text
distance = abs(Ax + By + C) / sqrt(A² + B²)
```

`L1` の両側に距離 `d0` の平行線を作るには、`n = sqrt(A² + B²)` として `C` だけを変える。

```text
L1:      Ax + By + C = 0
offset+: Ax + By + (C - d0*n) = 0
offset-: Ax + By + (C + d0*n) = 0
```

ルートを `Q(t) = O + tD` と置くと、あるオフセット直線 `Ax + By + C' = 0` との交点の `t` は次で直接得られる。

```text
denominator = A*Dx + B*Dy
t = -(A*Ox + B*Oy + C') / denominator
Q = O + tD
```

`denominator` が 0 に近いとき、ルートとその直線は平行で交点はない。非常に小さい値で割ると非現実的に大きな座標を作るので、`epsilon` を使って「平行」として扱う。

## 無限直線ルートの解析的アルゴリズム

`L1` とルートのなす角が 0 でなければ、`offset+` と `offset-` の各々に 1 個ずつ交点があり、通常は厳密解が 2 個得られる。`d0 = 0` では 2 本のオフセット直線が `L1` 自身と重なるため、候補は 1 個にまとめる。

```cpp
constexpr double kEpsilon = 1e-9;

double norm(const Line& line) {
    return std::hypot(line.a, line.b);
}

double distanceToLine(Point p, const Line& line) {
    return std::abs(line.a * p.x + line.b * p.y + line.c) / norm(line);
}

std::optional<Point> intersect(const RouteLine& route, const Line& line) {
    const double denominator = line.a * route.direction.x
                             + line.b * route.direction.y;
    if (std::abs(denominator) <= kEpsilon) {
        return std::nullopt; // 平行。巨大な t を作らない。
    }

    const double numerator = line.a * route.origin.x
                           + line.b * route.origin.y + line.c;
    const double t = -numerator / denominator;
    return Point{
        route.origin.x + t * route.direction.x,
        route.origin.y + t * route.direction.y,
    };
}
```

候補生成と選択は、次のように小さく分けると、全点独立であることがコードにも表れる。

```cpp
struct CorrectionResult {
    Point point;
    double error;
    bool exact; // error <= epsilon
};

double squaredDistance(Point lhs, Point rhs) {
    const double dx = lhs.x - rhs.x;
    const double dy = lhs.y - rhs.y;
    return dx * dx + dy * dy;
}

std::optional<CorrectionResult> correctOnePoint(
    Point original,
    const Line& originalBase,
    const Line& movedBase,
    const RouteLine& route)
{
    const double d0 = distanceToLine(original, originalBase);
    const double n = norm(movedBase);
    if (n <= kEpsilon) {
        return std::nullopt; // 壊れた基準直線
    }

    const Line offsets[] = {
        {movedBase.a, movedBase.b, movedBase.c - d0 * n},
        {movedBase.a, movedBase.b, movedBase.c + d0 * n},
    };

    std::vector<Point> candidates;
    for (const Line& offset : offsets) {
        if (const auto point = intersect(route, offset)) {
            const bool duplicate = std::any_of(
                candidates.begin(), candidates.end(),
                [&](Point other) { return squaredDistance(*point, other) <= kEpsilon * kEpsilon; });
            if (!duplicate) candidates.push_back(*point);
        }
    }

    if (!candidates.empty()) {
        // すべて error=0。第2優先の移動距離だけで選べる。
        const auto best = std::min_element(
            candidates.begin(), candidates.end(),
            [&](Point lhs, Point rhs) {
                return squaredDistance(lhs, original) < squaredDistance(rhs, original);
            });
        return CorrectionResult{*best, 0.0, true};
    }

    // 無限直線で交点がないのは、route が movedBase と平行な場合だけ。
    // 距離はルート全体で一定なので、P (route.origin) を返す。
    const double error = std::abs(distanceToLine(route.origin, movedBase) - d0);
    return CorrectionResult{route.origin, error, error <= kEpsilon};
}
```

上の例には `#include <algorithm>`, `<cmath>`, `<optional>`, `<vector>` が必要である。実運用では `std::isfinite` を使い、入力・途中計算・出力が有限値かも検査する。

## 平行・ほぼ平行の場合

無限直線ルートについては、次の 2 通りだけである。

| 条件 | `distance(Q, L1)` | 最適解 |
|---|---:|---|
| ルートが `L1` と交差する | ルート上で変化する | 距離 `d0` の平行線との交点。通常 2 個、`d0=0` は 1 個 |
| ルートが `L1` と平行 | ルート上で一定 | 完全一致ならルート上の全点が同率。そうでなければ全点が同じ誤差なので、最短移動の `P` |

「ほぼ平行」は `abs(A*Dx + B*Dy) <= epsilon` で判定する。ただし `1e-9` はすべての座標スケールに適切とは限らない。座標がピクセル程度ならよい出発点だが、数百万単位の値を扱うなら、`epsilon * (abs(A*Dx) + abs(B*Dy) + 1)` のような相対判定、または入力スケールをそろえる設計を検討する。

## 線分・半直線へ拡張する場合

ここまでの `RouteLine` は無限直線である。実際の「移動可能ルート」が線分や半直線なら、同じ交点計算で得た `t` が許可範囲内にあるか確認する。

```text
無限直線:  -∞ < t < +∞
半直線:     0 <= t
線分:       0 <= t <= 1   （direction = end - start とする場合）
```

2 本の平行線との交点が範囲外なら、完全一致候補として採用しない。残った候補がなければ、無限個の点を刻み幅で探索する必要はない。`| |αt+β| - d0 |` は区分的な直線なので、許可範囲の端点と、範囲内にある `αt+β = ±d0` の解を候補にすれば解析的に最小値を選べる。

この区別は API にも表すべきである。「無限直線として計算した」のに画面外や線分外の点を返さないよう、ルート種別と `t` の範囲を明示する。

## テスト観点

テストは点群ではなく、必ず 1 点の関数 `correctOnePoint` を直接呼ぶ。少なくとも次を確認する。

| ケース | 入力の要点 | 期待 |
|---|---|---|
| 1 | `d0=5`、ルートが `L1` を横切る | 選んだ点の誤差が epsilon 以下 |
| 2 | `L1` の両側に候補がある | `P` から近い候補を選ぶ |
| 3 | `d0=0` | ルートと `L1` の交点を返す |
| 4 | ルートが `L1` と平行 | 例外・NaN・巨大座標を出さず、`P` と妥当な誤差を返す |
| 5 | 垂直線・水平線 | 傾きを使わず正しく処理する |
| 6 | ほぼ平行 | epsilon 境界で不安定な巨大座標を返さない |

浮動小数点の値は `==` ではなく `abs(actual - expected) <= epsilon` で比較する。特に「厳密解」のテストも、計算機上では `error <= epsilon` を確認する。

## 実装レビューのチェックリスト

- [ ] `d0` は符号なしの垂直距離になっている
- [ ] 点ごとに独立に `d0` とルートを入力し、他点を参照していない
- [ ] `L1` から `±d0` の平行線を生成している
- [ ] 完全一致候補を先に探し、候補 2 個では移動距離で決めている
- [ ] 平行判定で小さい分母を割っていない
- [ ] 垂直線を傾きで特別扱いしていない
- [ ] 線分・半直線なら `t` の許可範囲を検査している
- [ ] 無効な直線、ゼロ方向、NaN/inf の入力契約が定義されている

この方法は候補数が最大 2 個で、各点あたり定数時間 `O(1)` である。全点をまとめた最適化も、刻み幅つき総当たりも不要で、意図した「各点の元の距離を可能な限り保つ」という条件をそのまま実装できる。
