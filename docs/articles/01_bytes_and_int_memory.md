# 1バイトはなぜ 0〜255 なのか

## int 100 の2バイト目を書き換えると何が起きるのか

プログラムでバイナリデータやバッファを扱っていると、よく次のような話が出てきます。

```cpp
uint8_t* buffer;
```

または、

```cpp
int x = 100;
```

このとき、

- 「int は4バイトって聞くけど、100という数値を4バイトに入れているの？」
- 「2バイト目を直接いじったらどうなるの？」
- 「1バイトで足りるなら uint8_t でよくない？」

という疑問が出てきます。

この記事では、まず **1バイトとは何か** から整理し、そのあとで **int 100 の2バイト目を書き換えたら何が起きるのか** を説明します。

---

## 1バイトとは何か

コンピュータのデータは、最終的には 0 と 1 の並びで表現されています。

この 0 または 1 の1つ分を **1ビット** と呼びます。

```
1bit = 0 または 1
```

つまり、1ビットでは2通りの状態を表せます。

```
0
1
```

では、2ビットならどうでしょうか。

```
00
01
10
11
```

2ビットでは4通りです。

3ビットなら、

```
000
001
010
011
100
101
110
111
```

8通りです。

つまり、ビット数が1つ増えるたびに、表現できるパターン数は2倍になります。

| ビット数 | 表現できるパターン数 |
|----------|----------------------|
| 1bit     | 2通り                |
| 2bit     | 4通り                |
| 3bit     | 8通り                |
| 4bit     | 16通り               |
| 8bit     | 256通り              |

そして、**1バイトは8ビット** です。

```
1バイト = 8ビット
```

したがって、1バイトでは、

```
2^8 = 256通り
```

の値を表現できます。

---

## なぜ 0〜255 なのか

ここで注意したいのは、**256通りある** ということと、**最大値が256である** ということは違うという点です。

コンピュータの整数は、多くの場合 0 から数え始めます。

そのため、256通りの値を表す場合、範囲はこうなります。

```
0 〜 255
```

つまり、

```
0, 1, 2, 3, ..., 254, 255
```

これで合計256個です。

1バイトを2進数で書くと、最小値はこうです。

```
00000000
```

これは10進数で **0** です。

最大値はこうです。

```
11111111
```

これは10進数で **255** です。

なぜなら、それぞれの桁には次の重みがあるからです。

```
128  64  32  16  8  4  2  1
```

全部が 1 なら、

```
128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255
```

になります。

だから、1バイトで表せる符号なし整数は、

```
0〜255
```

です。

---

## uint8_t は「1バイトの符号なし整数」

C++には `uint8_t` という型があります。

```cpp
#include <cstdint>
uint8_t value = 100;
```

`uint8_t` は、意味としては次の型です。

```
8bit unsigned integer
```

日本語にすると、

```
8ビットの符号なし整数
```

です。

**符号なし** というのは、マイナスを扱わないという意味です。

そのため、`uint8_t` の範囲はこうなります。

```
0〜255
```

つまり、`uint8_t` は1バイトで表現できる整数です。

---

## int は何バイトなのか

一方、C++の `int` は多くの環境で4バイトです。

```cpp
int x = 100;
```

この場合、`x` はメモリ上でだいたい4バイト分の領域を使います。

```
int = 4バイト
```

4バイトということは、

```
4バイト = 32ビット
```

です。

つまり、`int` は `uint8_t` よりも大きな範囲の数値を扱えます。

一般的な4バイトの `int` なら、だいたい次の範囲です。

```
-2,147,483,648 〜 2,147,483,647
```

かなり大きな数まで扱えます。

---

## int 100 はメモリ上でどう入るのか

では、次のコードを考えます。

```cpp
int x = 100;
```

100を16進数で表すと、こうです。

```
100 = 0x64
```

`int` が4バイトなら、本来は次のように4バイト分で表されます。

```
0x00000064
```

バイト単位で書くと、こう見えます。

```
00 00 00 64
```

しかし、実際の多くのPCでは **リトルエンディアン** という並び方をします。

リトルエンディアンでは、小さい桁のバイトから先にメモリへ置かれます。

そのため、メモリ上ではこうなります。

```
64 00 00 00
```

イメージとしてはこうです。

```
int x = 100;
メモリ上:
[ 64 ][ 00 ][ 00 ][ 00 ]
  1B    2B    3B    4B
```

ここでの `64` は16進数です。
10進数では `100` です。

---

## 2バイト目をいじったらどうなるのか

ここが重要です。

さきほどの `int x = 100;` は、メモリ上では次のようになっていました。

```
[ 64 ][ 00 ][ 00 ][ 00 ]
```

では、2バイト目を `00` から `01` に変えたらどうなるでしょうか。

```
変更前:
[ 64 ][ 00 ][ 00 ][ 00 ]
変更後:
[ 64 ][ 01 ][ 00 ][ 00 ]
```

リトルエンディアンでは、この並びは数値として次の意味になります。

```
0x00000164
```

10進数にすると、

```
356
```

です。

つまり、`int x = 100;` の2バイト目を書き換えると、

```
100 → 356
```

のように値が変わります。

なぜなら、各バイトには次のような重みがあるからです。

```
[ 64 ][ 01 ][ 00 ][ 00 ]
  ↑     ↑     ↑     ↑
 1の位  256の位 65536の位 16777216の位
```

2バイト目は、単なる「2番目の箱」ではありません。
数値全体の中では **256の位** を担当しています。

なので、

```
0x64 = 100
0x01 × 256 = 256
100 + 256 = 356
```

になります。

---

## サンプルコードで確認する

実際に確認するなら、次のようなコードになります。

```cpp
#include <iostream>
#include <cstdint>

int main() {
    int x = 100;

    // int型の変数xを、1バイトずつ見られるようにする
    // uint8_t* にキャストすると、xのメモリをバイト列として扱える
    uint8_t* p = reinterpret_cast<uint8_t*>(&x);

    std::cout << "変更前 x = " << x << std::endl;

    // xの中身を1バイトずつ表示する
    std::cout << "変更前のバイト列: ";
    for (int i = 0; i < sizeof(int); ++i) {
        std::cout << std::hex << static_cast<int>(p[i]) << " ";
    }
    std::cout << std::dec << std::endl;

    // 2バイト目を 0x01 に変更する
    // p[0] が1バイト目、p[1] が2バイト目
    p[1] = 0x01;

    std::cout << "変更後 x = " << x << std::endl;

    // 変更後のバイト列を表示する
    std::cout << "変更後のバイト列: ";
    for (int i = 0; i < sizeof(int); ++i) {
        std::cout << std::hex << static_cast<int>(p[i]) << " ";
    }
    std::cout << std::dec << std::endl;

    return 0;
}
```

多くの環境では、次のような結果になります。

```
変更前 x = 100
変更前のバイト列: 64 0 0 0
変更後 x = 356
変更後のバイト列: 64 1 0 0
```

---

## じゃあ数値が小さいなら uint8_t でよくないのか

ここで自然にこう思うはずです。

> 100みたいな小さい数値なら、intじゃなくてuint8_tでよくない？

これは半分正しいです。

値の範囲が 0〜255 に確実に収まるなら、`uint8_t` で表現できます。

```cpp
uint8_t value = 100;
```

この場合、使うメモリは1バイトです。

```
[ 64 ]
```

`int` のように4バイトは使いません。

ただし、何でも `uint8_t` にすればよいわけではありません。

---

## uint8_t を使うべき場面

`uint8_t` は、単に「小さい整数」だから使うというより、**1バイトのデータであることに意味がある場面** で使います。

たとえば次のような場面です。

- バイナリファイルの中身を1バイトずつ読む
- 画像のRGB値を扱う
- 通信データのパケットを扱う
- ファイルフォーマットの1バイト項目を扱う
- メモリバッファを直接操作する

こういう場面では、`uint8_t` は非常に自然です。

```cpp
std::vector<uint8_t> buffer;
```

これは、

```
バイト列を扱っています
```

という意味がはっきりします。

---

## int を使うべき場面

一方で、普通の数値計算なら `int` の方が自然です。

たとえば、

```cpp
int count = 100;
int score = 80;
int frame = 500;
```

のような値です。

これらは「1バイトのデータ」として扱いたいわけではなく、普通に数値として計算したい値です。

その場合、`int` の方が扱いやすいです。

理由は、`int` はCPUにとって自然なサイズであることが多く、計算にも向いているからです。

---

## uint8_t の注意点

`uint8_t` は便利ですが、注意点もあります。

特にC++では、`uint8_t` は内部的に `unsigned char` として扱われることがあります。

そのため、次のように出力すると、

```cpp
uint8_t value = 100;
std::cout << value << std::endl;
```

数値の `100` ではなく、文字として表示されることがあります。

数値として表示したい場合は、`int` に変換します。

```cpp
std::cout << static_cast<int>(value) << std::endl;
```

これは初心者がかなりハマりやすいポイントです。

---

## まとめ

1バイトは8ビットです。

```
1バイト = 8ビット
```

8ビットでは256通りのパターンを表せます。

```
2^8 = 256
```

そのため、符号なし整数として使う場合は、

```
0〜255
```

を表現できます。

`uint8_t` は1バイトの符号なし整数なので、

```
0〜255
```

の値を持てます。

一方、`int` は多くの環境で4バイトです。

```cpp
int x = 100;
```

と書くと、100という数値が4バイトの領域に格納されます。

リトルエンディアン環境では、メモリ上ではだいたい次のように並びます。

```
[ 64 ][ 00 ][ 00 ][ 00 ]
```

この2バイト目を `01` に変えると、

```
[ 64 ][ 01 ][ 00 ][ 00 ]
```

となり、数値は

```
100 → 356
```

のように変わります。

つまり、**バイト列を直接いじるということは、数値の内部表現そのものを書き換えるということ** です。

- 普通の数値計算なら `int`
- 1バイト単位のデータやバイナリを扱うなら `uint8_t`

この違いを理解すると、バッファ、バイナリ、構造体、ファイルフォーマットの話がかなり見えやすくなります。
