# 関数を返す関数

C++ では関数も「値」として扱える。  
文字列や整数を返すのと同じように、関数を返す関数を書くことができる。

この記事では、**関数ポインタ**を使って「文字列から対応する処理を取り出す」仕組みを段階的に説明する。

---

## 第1章：関数ポインタとは何か

C++ では、関数はメモリ上のある番地に存在する。  
その番地（アドレス）を格納できる変数が**関数ポインタ**だ。

```cpp
int add_one(int x) { return x + 1; }

int (*fp)(int) = add_one;  // add_one の番地を fp に格納
int result = fp(5);        // fp を経由して add_one を呼ぶ → 6
```

`int (*fp)(int)` という型は、「`int` を受け取って `int` を返す関数」へのポインタを意味する。

括弧が多くて読みにくいので、`using` で型エイリアスを作るのが実務的な書き方だ。

```cpp
using FuncPtr = int(*)(int);

FuncPtr fp = add_one;
int result = fp(5);  // 6
```

---

## 第2章：関数を返す関数を作る

関数ポインタを変数に格納できるということは、**戻り値として返すこともできる**。

たとえば、「文字列を受け取って、対応する関数を返す関数」はこう書く。

```cpp
#include <iostream>
#include <string>
#include <stdexcept>

using FuncPtr = int(*)(int);

int add_one(int x)       { return x + 1; }
int multiply_by_two(int x) { return x * 2; }
int square(int x)        { return x * x; }

FuncPtr get_func(const std::string& name)
{
    if (name == "add_one") { return add_one; }
    if (name == "double")  { return multiply_by_two; }
    if (name == "square")  { return square; }

    throw std::invalid_argument("unknown function name: " + name);
}

int main()
{
    FuncPtr func = get_func("square");
    int result = func(5);
    std::cout << result << std::endl;  // 25
}
```

`get_func` は文字列を受け取り、対応する `FuncPtr` を返している。  
戻ってきた `func` はただの変数で、`func(5)` と書けばそのまま呼び出せる。

---

## 第3章：何が嬉しいのか

「素直に `if` で分岐すればいいのでは」と思うかもしれない。

```cpp
// 分岐を呼び出し側に書く場合
std::string name = "square";
int result = 0;

if (name == "square")        result = square(5);
else if (name == "add_one")  result = add_one(5);
// ...
```

これでも動くが、同じ分岐が複数箇所に散らばるとすぐ壊れやすくなる。  
「どの文字列がどの関数に対応するか」という知識を1か所に集めることができるのが、関数を返す関数の強みだ。

```cpp
// 分岐の知識を get_func に集約する
FuncPtr func = get_func(name);
int result = func(5);
```

呼び出し側は「どの関数が来るか」を知らなくていい。  
`get_func` に問い合わせて、返ってきたものを呼ぶだけになる。

---

## 第4章：例外で「不正な名前」を伝える

`get_func` は知らない名前を受け取ったとき、`std::invalid_argument` を投げる。

```cpp
throw std::invalid_argument("unknown function name: " + name);
```

`nullptr` を返す設計にすることもできるが、その場合は呼び出し側が毎回 null チェックをしなければならない。

```cpp
// nullptr を返す設計だと呼び出し側が煩雑になる
FuncPtr func = get_func("typo");
if (func != nullptr)
{
    func(5);
}
```

「不正な名前は想定していない」という設計であれば、例外を投げて即座にエラーを知らせるほうが明確だ。  
呼び出し側は null チェックなしで `func(5)` と書ける。

---

## 第5章：より現代的な書き方 ―― `std::function`

C++11 以降は `std::function` を使うとより柔軟に書ける。  
ラムダ式やクロージャも格納できるので、関数ポインタより表現力が高い。

```cpp
#include <functional>

using Func = std::function<int(int)>;

Func get_func(const std::string& name)
{
    if (name == "add_one") return [](int x) { return x + 1; };
    if (name == "double")  return [](int x) { return x * 2; };
    if (name == "square")  return [](int x) { return x * x; };

    throw std::invalid_argument("unknown function name: " + name);
}
```

`std::function<int(int)>` は「`int` を受け取り `int` を返す何か」を格納できる型だ。  
通常の関数、ラムダ、関数オブジェクトのいずれも入る。

ただし `std::function` は内部で動的確保を行うことがあるため、  
パフォーマンスが厳しい場面では素の関数ポインタのほうが適している。

---

## 判断基準まとめ

| 状況 | 適した書き方 |
| :--- | :--- |
| 通常の関数のみ格納する | `using FuncPtr = 戻り値型(*)(引数型)` |
| ラムダやキャプチャを使いたい | `std::function<戻り値型(引数型)>` |
| 「不正な引数はない」前提 | 例外を投げる |
| 「見つからない場合」を呼び出し側に委ねる | `nullptr` を返す（要 null チェック） |

## 理解度チェック

次のコードについて、`result` の値が何になるかを答えてほしい。

```cpp
using FuncPtr = int(*)(int);

int double_it(int x) { return x * 2; }
int negate(int x)    { return -x; }

FuncPtr choose(bool flag)
{
    return flag ? double_it : negate;
}

int main()
{
    FuncPtr f = choose(false);
    int result = f(10);
}
```

**正解：`-10`**

- `choose(false)` は `negate` を返す
- `f(10)` は `negate(10)` を呼び出し、`-10` になる

> **ポイント：** 三項演算子で関数ポインタを選んで返すこともできる。  
> `double_it` と `negate` は同じ型 `FuncPtr` なので、どちらも戻り値に使える。
