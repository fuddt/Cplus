# 1. そもそも「バイナリファイル」とは何か？

## メモリのバイト列を「そのままディスクへダンプした」もの

ファイルを保存するとき、方法は2つしかありません。

```text
【テキスト形式（JSON, CSV, XML）】
人間が読める「文字コード」に変換して保存する
1000000 という数値 ──> "1000000"（7文字 = 7バイト消費）

【バイナリ形式（画像, 音声, 独自形式）】
メモリ上の生バイト列をそのままディスクに書き写す
1000000（0x000F4240） ──> [ 40 42 0F 00 ]（4バイトで完結！）
```

* **サイズが圧倒的に小さい**（無駄な文字変換がない）
* **読み書きが超高速**（パース処理が不要、メモリに一撃でロード）

# 2. バイナリファイルフォーマットの共通構造

## 「ヘッダー（固定長）」＋「データ部（可変長）」の2層設計

画像や音声、独自ファイルは、ほぼ例外なくこの構造です。

```text
+─────────────────────────────────+─────────────────────────────────+
|     ヘッダー部（固定サイズ）     |      データ部（可変サイズ）      |
+─────────────────────────────────+─────────────────────────────────+
| マジックナンバー (2〜4B)         | 実際の画像ピクセル配列            |
| ファイルバージョン (2B)          | レコードデータ                    |
| データ幅・高さ・要素数 (8B)      | ペイロード本文                    |
| ペイロードのバイト長 (4B)        |                                 |
+─────────────────────────────────+─────────────────────────────────+
```

* 先頭に **「このファイルは何者か？」** を表すメタデータを置く
* 後半に **「本体の巨大なデータ（バイト配列）」** がそのまま続く

# ヘッダーの具体例（画像ファイル）

## C++の構造体としてヘッダーを定義する

```cpp
struct ImageHeader {
    uint8_t magic[2];   // ファイル識別子（"BM" など）
    uint8_t version[2]; // フォーマットのバージョン
    uint32_t width;     // 画像の横幅
    uint32_t height;    // 画像の高さ
    uint32_t dataSize;  // 後続するデータ部のバイト数
};
```

* ファイルの先頭 `sizeof(ImageHeader)` バイトを読むだけで、
  **「どんな画像で、何バイト読めばいいか」** が一瞬でわかる
* 第3回で学んだ **「構造体ビュー」** を被せて一撃で解釈できる

# 3. 現場のトラウマ：`std::ios::binary` を忘れた悲劇

## Windows環境でファイルが突然壊れる恐怖のバグ

C++でファイルを開くとき、指定を怠ると大惨事が起きます。

```cpp
// 【絶対にやってはいけない間違い】
std::ifstream file("image.bin"); // binary フラグがない！
```

* Windowsのテキストモードは、**改行文字（0x0A）を見つけると勝手に 0x0D 0x0A に水増し** する
* 画像やバイナリの中に偶然 `0x0A`（十進数で10）が含まれていると、
  ファイルを開いた瞬間にバイトが挿入され、**以降の全データがズレて即死**
* **教訓：バイナリを触るときは `std::ios::binary` を絶対に忘れるな**

---

# 4. C++でのファイルサイズ取得イディオム

## ファイル末尾へジャンプして位置を測る

バイナリファイルを読み込むには、まず **「何バイトあるか」** を知る必要があります。

```cpp
std::ifstream file(filePath, std::ios::binary);

// 1. ファイルの末尾へシーク（移動）
file.seekg(0, std::ios::end);

// 2. 現在の読み取り位置（=ファイルサイズ）を取得
std::streamsize fileSize = file.tellg();

// 3. 読み取り位置を先頭に戻す
file.seekg(0, std::ios::beg);

// 4. 正確なサイズのバッファを確保！
std::vector<uint8_t> buffer(static_cast<size_t>(fileSize));
```

* `seekg(0, end)` → `tellg()` は C++ の定番イディオム

---

# 5. ファイル全体を一撃でメモリへ吸い上げる

## `file.read` でバッファへダイレクトに流し込む

```cpp
// ifstream::read は char* を要求するためキャストする
if (!file.read(reinterpret_cast<char*>(buffer.data()), fileSize)) {
    throw std::runtime_error("ファイルの読み込みに失敗しました");
}
```

```text
ディスク上のファイル (10MB)
      │
      │ (file.read による一括DMA転送)
      ↓
std::vector<uint8_t> buffer (10MB)
```

* 1バイトずつ読むのではなく、**OSのDMA転送で一括ロード** する
* 100MBの巨大データでも一瞬でメモリ上に展開完了する

# 6. 実践：バイナリパッチ処理の流れ

## 読み込んだバッファを構造体で触り、ファイルへ書き戻す

```text
[ ステップ 1: ロード ]
バイナリファイル ──> std::vector<uint8_t> buffer に一括読み込み
                          │
[ ステップ 2: 構造体ビュー ]
MetaData* meta = reinterpret_cast<MetaData*>(buffer.data());
meta->owner[0] = 99; // 特定フィールドを書き換え！（パッチ）
                          │
[ ステップ 3: 上書き保存 ]
buffer ──(ofstream::write)──> バイナリファイルへ書き戻す
```

* オフセットを手計算せず、**構造体メンバ名で安全にパッチ** を当てる
* これがゲームのセーブデータ編集や、機器設定ファイル書き換えの基本形

---

# 書き戻しの実装コード

## `std::ofstream` にバッファをそのまま渡す

```cpp
void writeBinaryFile(const std::string& filePath,
                     const std::vector<uint8_t>& buffer) {
    // バイナリモードで新規作成・上書き
    std::ofstream file(filePath, std::ios::binary);
    if (!file) throw std::runtime_error("ファイル作成失敗");

    // メモリ上のバイト列を一括書き出し
    file.write(reinterpret_cast<const char*>(buffer.data()),
               static_cast<std::streamsize>(buffer.size()));
}
```

* 読み込みと同じく、`file.write` 一発でディスクへ書き出せる
* メモリの状態がそのままファイルとして永続化される

# 7. 現場の防衛設計① マジックナンバーの検証

## 「違うファイルを開いた事故」を水際で防ぐ

バイナリファイルは拡張子（`.dat` や `.bin`）を変えられても中身は変わりません。
誤って違うファイルを読み込むと、構造体が壊れて大惨事になります。

```cpp
if (header->magic[0] != 'M' || header->magic[1] != 'Y') {
    throw std::runtime_error("不正なファイル形式です（マジック不一致）");
}
```

```text
PNGファイル: 先頭 8バイトが必ず [ 89 50 4E 47 0D 0A 1A 0A ]
BMPファイル: 先頭 2バイトが必ず [ 42 4D ] ("BM")
PDFファイル: 先頭 4バイトが必ず [ 25 50 44 46 ] ("%PDF")
```

* ファイル先頭の固有シグネチャを必ずチェックするのが実務の鉄則

# 現場の防衛設計② バージョン互換性

## 将来フィールドが増えたとき、旧ファイルを読めるか？

```text
【バージョン 1 のファイル（12バイト）】
[ header (4B) ][ birthday (4B) ][ owner (4B) ]

【バージョン 2 で追加されたファイル（16バイト）】
[ header (4B) ][ birthday (4B) ][ owner (4B) ][ jockey (4B) ]
```

* ヘッダーにバージョン番号（`version`）を入れておかないと、
  旧バージョンのファイルを新プログラムで読んだ瞬間に **領域外アクセスで死ぬ**
* 「現在のファイルサイズ ≥ 必要サイズ」のチェックも絶対に怠らない

# 本日のまとめ

## 持ち帰ってほしい 4つの重要ポイント

* **① バイナリファイルはメモリの生ダンプ**
  * テキスト変換を挟まないため超軽量＆超高速
* **② `std::ios::binary` は絶対につける**
  * Windowsでの改行コード自動置換による破損を完全防御
* **③ `seekg(0, end)` + `tellg()` でサイズ取得**
  * 正確なバッファを確保して `file.read` で一撃ロード
* **④ マジックナンバーとバージョンを必ず検証する**
  * 不正ファイルや旧バージョンの読み込みによるクラッシュを防ぐ
