# 生成AIの「ガチャ」要素との付き合い方

## ― 微調整できるレビュー環境を作った ―

生成AIで資料を作るときの、私なりのやり方

---

# AIで資料を作るのは、簡単

* 簡単な指示でも、数秒で形になる
* 見た目も整っている

**でも、細部を読むと…**

* 変な言い回し
* 誤解を生む表現

**作るのは一瞬。レビューは人間に残る。**

---

# SNSでよく見る「一発でできました！」

* 「一発でこんなのができました！」
* 実際は、そんなに都合よく思い通りにはならない

**現実に即して補足するなら…**

**「（こだわりがなければ）一発でこんなのできます」**

---

# 一発で思い通りは出ない

* 想像と違うものが、大量に出てくる。読んで直すのが辛い
* イメージを100%伝えるのは、人間相手でも無理

**これは、AIだけの問題ではない。違いは「途中で気づけるか」**

```
人間： 書く → 気づく → 直す → 書く → 気づく…
AI  ： 一瞬で最後まで出力 ……… → 読んで、気づく
```

* 人間は、書く間に途中で気づける
* AIは、最後まで一気に出す。ずれが大きくなってから見つかる

---

# よくあるAIとの認識のズレ

## たとえば：旅行プランのノウハウ集

* ほしいのは「旅行プランの組み立て方」のノウハウ集
* 「伊豆旅行を例に考えよう」とAIに相談する
* 出てきたのは「伊豆旅行の、旅行プランの組み立て方」

**ほしかったのは汎用的なもの。例にした題材に引っ張られた**

AIは、局所最適化に偏ることがある

# ズレたら、作り直させる前に認識を合わせる

```
作らせてみた → 思い通りじゃない
  ├ ✕ 作り直させる → また外れる
  └ ○ 認識を合わせる → AGENTS.md / CLAUDE.md に残す
```

* AIの理解と、自分の理解をすり合わせる

先ほどの例でいうと

### 目次を先に合わせたら、大きなズレは防げた

* テーマを一文にする（例：特定の場所に依存しない）
* 目次と、各章で語ることを先に確認する
* それから本文を書く

---

# 同じことを繰り返さないために

## ― 決まったことは、規約ファイルに残す ―

* 認識合わせで決まったことを、ここに書いておく
* AGENTS.md / CLAUDE.md ＝ AIが作業の前に読む、プロジェクトのルール集

※ 書き方などの詳細は、ネットにたくさんあるので、今回は話しません
※ これもまだ今回伝えたい主題ではありません

---

# 認識合わせ・規約ファイルを作る・・・ここまではよくある話

## ― それでも、ズレる ―

* 認識を合わせて、ルールも固めた
* それでも、要所要所でズレは出る
* 生成は一瞬で大量。レビューする量も大量
* 私も、最後に残るのは細部のレビューだった

### 残るのは、「レビューして直すコスト」

* 外れる確率は、ゼロにはならない
* ゼロにならない以上、外れたときのコストは**毎回**払い続ける
* 直しやすい環境は、一度作れば**次の作業でも使える**

**これが今後のAI活用で価値のある投資ではないかと思います**

---

# 「レビューもAIにやらせれば？」

## ― 問いは「責任を負えるか」―

* AIにレビューさせても、そのレビューを見る人間が要る
* 人間を外せるのは、AIだけで完結すると言い切れるときだけ

**AIが作り、AIが確認したものを商品として出す。**
**トラブルが起きたとき、責任を負えますか？**
**お客さんに、納得して買ってもらえますか？**

* どちらも大丈夫 → 全部AIに任せるのも、ありだと思う
* 難しい → 人間のレビューは残る。だから、そのコストを下げたい

# 私がAI生成物をレビューするために作ったもの

レビューを効率化するツールを作りました。名前は「slidekit」です。
今回は、スライド資料をAIに作らせる過程で作ったものを紹介します。

* Markdownを書くと、16:9のスライドで見られる
* PPTXに書き出せる
* Claude Code / Codex / Antigravity から使える

**この発表も、slidekitで作っています**

注意：話したいのは「このツールが便利です」ではなく、
AIで何かを作るなら、レビュー環境を整えると効率が上がる、ということです。


---

# ツールを作るときに考えたこと

## ― AIを使った生成でよくある悩みから ―

* 小さな直しでも、AIに頼むと**待たされる**
* 頼むと、直してほしい所以外も**変わってしまう**（またガチャ）
* 言葉で説明するより、**自分で直したほうが速い**

**この3つを改善したいと思いました**

---

# こだわり1：自分でその場で直せる

* 「VS Codeで開く」ボタンで、該当の行へジャンプ
* 小さな直しは自分で
* 大きな直しだけAIに頼む

**AIの返事を待たない**

---

# こだわり2：保存すると、すぐ反映

* 直す → 保存 → 見る が一瞬
* 書きながら確認する感覚に近づく

**AIにはなかった「途中で気づく」を、取り戻す**

---

# 使いながら足したもの

* はみ出し警告
* サムネイル一覧
* フォルダ単位の切り替え

**はみ出しは、目では見逃していた**

機械で分かることは、機械に任せる

---

# テクニック：レビュー専用のセッション

* 作ったセッションとは別の、新しいセッションで見直す
* 観点を渡す
* 指摘だけさせて、直させない

**余裕があれば、別のAIにも見せる**

---

# 限界

* 効果を数字では示せていない
* slidekitは個人用。画像は扱えない

---

# まとめ

* 一発で思い通りは出ない。外れる前提で考える
* 認識合わせとルールで、ズレは減らせる。でも、ゼロにはならない
* だから、レビュー環境（自分で直せる・すぐ反映）に投資する

**AIを雑に扱うと、ガチャになる**
