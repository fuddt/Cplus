# 01の復習：byte境界 と データ境界 は一致しない！

## アドレスの境界と、意味上の境界のズレ

第1回で、メモリは「8bit（1byte）のロッカー街」だと学びました。

```text
アドレスの境界（物理的な番地）:
|   byte (8bit)   |   byte (8bit)   |   byte (8bit)   |

意味上の境界（データの仕様）:
|       12 bit 画素 A        |       12 bit 画素 B        |
```

* 一般的な現代の環境では、メモリは **1byte（8bit）単位でアドレスが付けられている**
* しかし、画像や通信のデータは **12bitや10bit** など、バイト境界を無視して詰め込まれることがある
* アドレスの境界と意味の境界がズレるからこそ、**「生byte列を操る技術」** が不可欠になります

# まずゴールを確認：Packedデータを何に戻すのか？

## 「詰め込まれた24bit」を「2つの計算しやすい16bit整数」へ戻す

bit演算のテクニックに入る前に、**「最終的にどんな形のデータに変換したいのか」** ゴールを明確にしましょう。

```text
【入力: カメラから届く状態（Packed 3バイト）】
3 byte の連続メモリ
┌──────────┬──────────┬──────────┐
│ byte 0   │ byte 1   │ byte 2   │
│ AAAAAAAA │ AAAABBBB │ BBBBBBBB │
└──────────┴──────────┴──────────┘

              ↓ 復元（Unpack）

【ゴール: プログラムで計算したい状態（Unpacked 16bit整数 × 2）】
uint16_t pixelA
┌─────────┬──────────────┐
│  0000   │ AAAAAAAAAAAA │  ──> 1つの独立した数値（0〜4095）
└─────────┴──────────────┘
  上位4bit   画素Aの12bit

uint16_t pixelB
┌─────────┬──────────────┐
│  0000   │ BBBBBBBBBBBB │  ──> 1つの独立した数値（0〜4095）
└─────────┴──────────────┘
  上位4bit   画素Bの12bit
```

* **Packing（パッキング）**：複数データを隙間なくバイト列へ詰め込むこと（※データ圧縮ではなくbitレイアウトへの詰め込み配置）
* **Unpacking（アンパッキング）**：詰め込まれたバイト列から、計算しやすい整数型へ復元すること
* **今回のゴール**：12bit画素値を `uint16_t` の **「下位12bit」へ右詰め（上位4bitは0）** して復元する。これにより、`pixelA` は `0〜4095` の普通の整数値としてそのまま計算できるようになります！
